## 2026-11-09_153929_1794235169: Version 1.2.23: Web UI themes (D63) and dark-mode fixes

- **Dark-mode bugs found by eye (mock nox in the built-in browser):** the Done column's percentage inherited the muted row colour on stopped, queued and finished rows, grey on grey at about 2:1; the scheduler's cells were hard-coded, a white "Turn off" block in dark; the Pieces canvas painted downloading pieces in the light orange whatever the mode; the Speed graph's line colours were JavaScript constants; the modal backdrops one fixed grey; no `theme-color` for a phone's browser chrome; the canvases never repainted on a scheme change. Fixed with new tokens on `:root` (`--bar-fg`, `--graph-dl`, `--graph-ul`, `--scrim`, `--sched-full/-limited/-off/-seed`, Off being `var(--bg)`), `theme-color` metas for light and dark, a `forced-colors` block that keeps the bars' fills under Windows High Contrast, and the dark seed green `#3f9e55` for 3:1 text (the palette's value).
- **Themes:** a theme is one CSS file of the 29 colour tokens plus `color-scheme`, loaded after `style.css` from `/themes/<id>.css`; `system` (the `prefers-color-scheme` behaviour) stays the default with no file. Built-ins, embedded and each under 4 KiB: Light, Dark, Midnight, Slate, Solarized Dark, Solarized Light, High Contrast and Postal Rook (the brand's paper, navy, stamp red, kraft and gold). Third-party files from `webui/themes` under the settings directory (`--config-dir`; the host's settings folder hosted), named by their `/* name: ... */` comment, ids `[a-z0-9-]{1,40}`, 64 KiB at most, read per request; nothing is read when the folder is absent. `webui::theme` serves them before the login like the statics (ETag, `no-cache`, 304), refusing everything else by id shape before any path is built.
- **Two settings:** `webui.theme` on Preferences > UI Settings > Display Options for everyone (an ordinary preference, no current password; `hello` carries it and the `[id, name]` list) and "Theme in this browser" beside it, also the phone More menu's Theme submenu (`pa.theme` in localStorage), over the server's. The page caches the server's choice and applies the resolved theme as its first statement, so the login page is themed on a reload; a sheet swaps in only once loaded; a removed third-party file falls back to the server's choice, then System; both canvases repaint on a theme or scheme change. Strings `PrefTheme`, `PrefThemeBrowser`, `ThemeFollowServer`, `Theme*`, `WebTheme`, `PrefBadTheme` and two help texts in all 35 tables (machine-translated; Postal Rook rendered with each language's rook or crow).
- **Validation:** nox 84 unit tests (theme ids, the token completeness of every built-in file, third-party listing) and 44 `webui` tests including `themes_are_served_listed_and_chosen` (route, traversal refusals, size cap, listing, the preference's round trip and persistence across a restart); frontend 364 (tables complete and in order); clippy and fmt clean. By eye: Midnight, Postal Rook and a third-party file through Preferences and the browser-only picker, the phone menu, the themed login page, no CSP errors; `--no-state` has no settings folder, so third-party themes need a state directory. Not checked: a real phone, Safari, the hosted (Windows program) Web UI's folder, High Contrast on Windows.

## 2026-11-09_153839_1794235119: Version 1.2.22: a shared palette for the drawn parts; GTK bars and maps follow dark themes

- **Theme pass (owner, 2026-11-09; D63).** Audit of light and dark on all four UIs: the Web UI by eye in the built-in browser against a mock nox (desktop and phone width), GTK, macOS and Win32 by code. Findings: Win32 has no dark mode at all (designed in [DARKMODE.md](docs/DARKMODE.md), a later piece); GTK's piece bars, piece map and Blocks cell stayed white under a dark theme and the scheduler's Off cell was literal white everywhere; macOS was fine but for the scheduler grid; the Web UI's bugs are in 1.2.23 below.
- **Shared:** `frontend::palette::DrawPalette` with `LIGHT` and `DARK` (surface, bar background/frame/text, bar blue and green, requested blocks, graph lines, grid line, four availability shades), `for_dark`, `sched_cell` (Off is the surface colour, the other three modes µTorrent's `Mode::rgb`) and `blend` toward the bar background (replacing two "toward white" mixes). Tests: the two sets differ in every field, `blend` matches the old formula byte for byte over white, and the bar text keeps at least 3:1 over every bar fill in both sets (the dark green became `0x3f9e55` for it).
- **GTK:** the drawn widgets take `DrawPalette::for_dark(icons::dark())`; `is_dark` reads the XDG Settings portal's `org.freedesktop.appearance` `color-scheme` first (`portal::color_scheme`, `ReadOne` then `Read`, 300 ms) and follows its `SettingChanged` signal, then the prefer-dark flag and the theme name as before. The scheduler grid picks a change up when its dialog opens again.
- **Win32:** `details.rs`, the Done bar in `app.rs` and `sched_grid.rs` read `palette::LIGHT`; the same bytes as before (verified by the palette test and 114 Win32 tests). **macOS:** the scheduler's Off cell is `textBackgroundColor`.
- **Validation:** frontend 364 tests, Win32 114, clippy clean for frontend, Win32 and (type-checked for Linux through the stand-in pkg-config) GTK; `cargo fmt --check` clean. Not run: the GTK crate on the Xubuntu VM (the portal path in particular) and the Cocoa crate (two lines, APIs already in use there); both are BACKLOG "Themes" hand checks.
