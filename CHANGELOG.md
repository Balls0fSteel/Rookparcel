## 2026-11-10_202226_1794338546: Version 1.2.44: a bug review of everything since 1.2.30; five fixes

- **Asked by the owner:** look over the changes waiting for the release and fix the bugs found. `git diff v1.2.30..HEAD` read in five parts: core here, and four read-only agents for the frontend, nox and the Web UI, Win32, and GTK with the Mac crate.
- **Run Program, fixed (`core::run_program`):** a torrent that finished within one status update of being added (a small one, or one whose data was there) lost its "added" program: one waiting slot per torrent held the later event only. Both wait now. `shell_reads_codes` missed `-c` behind an option that takes a value (`bash -o pipefail -c "... %N"`, `--rcfile x -c`), fish's `--command=...`, `-C` and `--init-command`, and PowerShell's `-File` behind a `-Command` (part of the command there).

The label is restored first.
- **Hosted Web UI, fixed:** a loopback session read the host's Run Program lines (`/pa/prefs` and the shim's `autorun_*`), which no browser may change there; hidden like for a remote session.
- **Small:** a fetched tracker list with more valid lines than the 200 kept was weighed against the kept ones only and could be refused as "not a list"; GTK's Statistics window closes with the main window (`destroy_with_parent`).
- **Looked at, left:** a reviewer's guess that the dark list paint (1.2.31) leaves lists without `LVS_EX_DOUBLEBUFFER` black was pictured before and after a fix on the hidden desktop (RSS filters, empty): identical and right, nothing changed. Refusing a remote request that names a Run Program line with its stored value was tried and taken back: two tests pin "the same value is no change" as chosen. The reviewers' other findings are in BACKLOG "Statistics, trackers and Run Program" (found 2026-11-10 in review).
- **Validation:** tests on Windows: core lib (931), frontend (380 + 4), nox (all suites, 211), Win32 (140, one thread); `cargo check` of the workspace with the GTK and Mac crates. **Not done:** the GTK and Mac changes (one builder line; the shared `alerts.rs`) did not run on the VMs; no real transfer was repeated; the two Web UI changes ran in tests only.

## 2026-11-10_151945_1794320385: Version 1.2.41: Run Program on added and finished, without a shell, changeable only locally

- **Asked by the owner:** qBittorrent's "Run external program", carefully: attackers who got into exposed qBittorrent Web UIs set that option to download and run scripts (CVE-2023-30801; their fix was a random first password, the option stayed settable by any session). Chosen: local only with an opt-in for remote; events added and finished (D67).
- **Runner (`core::run_program`):** fed every alert like `MoveCompleted`, in the program that owns the engine (never a remote window, never the demo). Added: new torrents only (not duplicates, not restored). Finished: only when something was downloaded. The line is split into arguments first (blanks and double quotes, nothing else special) and qBittorrent's codes %N %L %F %D %Z %T %I %J %K are filled in afterwards per argument, control characters dropped; the program's path takes no code. No shell, no window, null input and output, 4 at once, 1,000 waiting.
- **Who may change the lines:** the GUIs locally; the Web UI through `prefs::RunGate`: a loopback request without a forwarding header, or nox started with `--webui-remote-run-program` (command line only, never stored), and in both cases the current password. A refused request is answered before its password is looked at and logged with its address. Not the qBittorrent API (`autorun_*` ignored, lines shown only to a local client), not the remote GUI protocol, not a hosted Web UI. nox warns at start when a line is on and the Web UI listens beyond loopback.
- **Clients:** Preferences > Advanced > Run Program in all four, from existing field kinds; `pref_pages::run_command_error` is the one rule for a line (empty, an open quote, a code in the program's path, too long).
- **Left out:** %C, %R and %G (the status the runner works from has no file count, root path or tags); a state-change event (µTorrent's second line).
- **Validation:** 6 runner tests, one starting a real process with a hostile name (quotes, `&`, `$(..)`, `%TEMP%`) and checking each argument arrives whole; a Core test; nox: one unit and five integration tests over rules A to I (local with password accepted and kept over a restart; remote with the right password refused, session alive, logged; the flag opens the gate but not the password; passwordless sessions and the shim refused; a remote GUI's `ApplySettings` changes nothing; hosted refused; one deliberate end-to-end run of the nox binary itself with `--version` on an add). Suites on Windows: core (935 and its integration tests), frontend (378), nox (210 in all) and Win32 (140, one thread), 1,823 tests, pass; the Mac crate's 10; clippy `-D warnings` for the workspace on Windows, the GTK crate (Linux target) and the Mac crate (both darwin targets); fmt. The Win32 page pictured in light and dark and in German, Hungarian and Thai, with `-Audit` clean for seven languages (the page's name is cut by a few pixels in the tree in German, as other nested names already are; the tree has a tooltip). The Web UI page driven in the built-in browser against a mock daemon (refusals, read-only presentation, 375 px, dark). **Not done:** "remote" was simulated with a forwarding header over loopback, not from a second machine; no `.bat` or `.cmd` target was run (the standard library's escaping is relied on); no program was started through a GUI's alert loop; the GTK and Mac pages never ran; in a remote window the page shows and stores lines that do nothing, without saying so; a logged-in remote client can lengthen `--log` with refused requests.
