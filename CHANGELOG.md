- **Site and docs:** `site/benchmarks.html` filled from the new file, its prose checked against it (idle CPU no longer "the least"), a "Since 1.0.1" section; the home page says "under a second and a half" and "under 0.2 %" for the Windows GUI; BENCHMARKS.md has the new results, the method changes and the run's duration. ## 2026-11-09_181244_1794244364: Version 1.2.29: the theme work tested on the VMs and this PC; four Win32 fixes, one GTK fix; release prepared

- **Test pass (owner, 2026-11-09: "full testing of the work done, through VMs and the real machine"):** the whole workspace's tests on this PC (core 923 and its integration suites, frontend 364, Win32 122, nox 84 + 40 + 16; all green), the GTK, frontend and nox tests on the Xubuntu VM (one failure explained: the HELP_TEXTS.md check sees no `docs/` in the pushed tree), the native Mac app built and run on the Mac VM in light and dark, the Windows program on the Windows 11 VM (`tools/win32-shots` on the VM's console session through `in-session.ps1`: light and dark captures at 100 %, a live flip of Windows' *Choose your mode*, dark and light at 150 % and 200 % after switching the VM to a 3840x2400 mode and `SPI_SETLOGICALDPIOVERRIDE`), the Web UI on the mock daemon in the browser (every built-in theme listed, a third-party file served and applied, the server's choice and the browser's override, `/themes/..%2f` and upper-case ids refused), and a read-only review of the whole diff since v1.2.21 (no security defect in `/themes/`; its two real findings are fixes 1 and 3 below).
- **Fixed, Win32 (found on the VM):** (1) under System a flip of Windows back to light was never seen: `ShouldAppsUseDarkMode` answers from the app mode once `SetPreferredAppMode(ForceDark)` is in force, so `theme::windows_dark` reads the registry's `AppsUseLightTheme` first and asks uxtheme only without it. (2) Connect to Remote, shown before the settings load, and every remote window were light in dark: `theme::init` now runs at the very start from the local ini's `ui.theme`, and a remote window's own folder takes the key over as it does the language. (3) Multi-line edits (the tracker boxes of Create and Properties) kept light scroll bars under `DarkMode_CFD`: they take `DarkMode_Explorer`; single-line edits keep CFD's dark frame. (4) The dark tab strip clipped its labels at 150 % ("Genera", "Tracker:"): the icon and text are centred in the item the control sized, instead of a fixed margin that does not scale as the control's padding does.
- **Fixed, GTK (found on the Xubuntu VM):** the Settings portal's `color-scheme` no longer takes part in `icons::is_dark`: plain GTK 4 widgets do not follow it (Greybird or GTK's default theme with `prefer-dark` paints light widgets), so it put dark icons and bars over light widgets. The GTK theme name, `gtk-application-prefer-dark-theme` and `GTK_THEME=<name>:dark` (which GTK applies without a word in its settings; it made the `Adwaita:dark` run light-iconed before) decide. The portal reading and its watch left `portal.rs`; the Background portal stays.
- **New:** `tools/win32-shots/flip-test.ps1` flips `AppsUseLightTheme` and broadcasts `WM_SETTINGCHANGE "ImmersiveColorSet"` as the Settings app does, with Preferences and then the Add URL prompt open, for a test machine.
- **Noted, not changed:** the file picker in dark follows Windows' own mode (a system dialog); the Mac dark snapshot showed the detail tab strip white without labels, which the unlocked VM's real screen (`screencapture`) then showed right: an artefact of `ROOKPARCEL_SNAPSHOTS`' `cacheDisplayInRect` with a layer-backed `NSSegmentedControl`, not the app; a Windows 10 1809 VM is still unchecked (BACKLOG "Themes").
- **CI on `main` (first run of the dark-mode commits):** Linux, macOS, MSRV and FreeBSD failed to build the Win32 crate: `mod theme;` lacked the `#[cfg(windows)]` gate every other module has, so uxtheme code was compiled into the non-Windows stub. Gated; the workspace lints clean for the Linux target with `-D warnings` from here. No version bump: the Windows program is unchanged and the stub never built.
- **Validation after the fixes:** the VM's flip test goes dark and back to light with the dialogs following; dark captures at 100, 150 and 200 % reviewed (Connect to Remote dark, dark scroll bars, full tab labels); the light capture at 100 % equals the pre-fix one but for the file picker's content, carets and timing; Win32 and frontend tests, clippy and fmt clean; the GTK crate type-checked for Linux here and built, tested and run on the VM in three modes (icons light under Greybird and under the portal's prefer-dark, dark under `Adwaita:dark`); the Flatpak metainfo has the 1.2.29 release; `docs/releases/1.2.29.md` written.
