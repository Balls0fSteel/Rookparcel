## 2026-11-06_200404_1793991844: 1.2.19's Mac notifications work once allowed

- The VM never showed them because Rookparcel's notifications were switched off in System Settings (its `com.apple.ncprefs` flags lack the "allowed" bit every allowed app has), so `UNUserNotificationCenter` answered "not allowed" without asking. Once the owner allowed them, the 1.2.19 release app showed "Download Complete" as a banner with Rookparcel in front and with Finder in front (usernoted: "Presenting ... as banner"). No code change; the notes now say to turn them on there if none appear.
- Found on the way: usernoted refuses the legacy `NSUserNotificationCenter` for this id ("You can't mix modern clients with legacy clients"), even in a process that never touches the modern centre, so the legacy fallback and the delegate 1.2.19 sets at the start do nothing. Harmless; BACKLOG "macOS" (A) has the cleanup. Checked with a test build that used one centre at a time, not committed.

## 2026-11-06_190632_1793988392: v1.2.19 tagged; the first native macOS release run built the draft

- **Fixed (release workflow):** the first trial run (Actions > Release on `main`) failed a universal app: `lipo -archs` prints `x86_64 arm64`, and the check's pattern `*" x86_64 "*" arm64 "*` needs a space on both sides of each name, which the two share. Each architecture is now looked for on its own. Only the workflow changed, so no version bump.
- Before pushing: the workspace clippy with Rust 1.99 on the Mac VM (this PC has 1.90; 1.99 broke CI at 1.2.5), clean. On `867f2eda`: CI, FreeBSD and a second trial green (Fuzz on `c1c26db2`, the same code). `v1.2.19` tagged there; the Release run made the draft with all 14 files and `SHA256SUMS`. The dmg is 7.4 MB (1.2.5's GTK one: 16.3 MB).
- **Mac app, tried:** on GitHub's Apple silicon runner the arm64 half ran 20 s and drew the Setup Guide, the x86_64 half answered `--version` under Rosetta. On the Intel VM the draft's dmg (its SHA-256 as listed) mounted, the ad-hoc signature verified, universal, `LSMinimumSystemVersion` 11.0, the plain version 1.2.19; a portable start reached the main window (21 DHT nodes, 50 MB), Quit took 204 ms and the defaults were put back. The live site still shows 1.2.5's macOS text, `update.txt` `stable=1.2.5`. **Not tried:** a real Mac (the owner's), Windows and Linux files by hand (the release job installs and uninstalls the setup itself; their only change since 1.2.5 is the engine fix).

## 2026-11-06_162621_1793978781: Version 1.2.19: the Mac GUI's slice L follow-ups; a stopped magnet reconnects

- **Fixed (engine):** a magnet stopped from its Add dialog ("Start torrent" unchecked) and started later waited `min_reconnect_time` (60 s) before reconnecting to the peer it got its metadata from (BACKLOG called it "never"). Leaving upload mode now removes the connections the pause just closed before it resets the peers' reconnect delay, the order libtorrent's immediate `disconnect` gives. New `swarm` tests: the dialog flow finishes from its `x.pe` peer, and a magnet added stopped keeps that peer across a restart. Separately, the VM's 256 KiB-piece stall did not reproduce over Windows loopback.
- **Mac:** a status-item click no longer covers an open dialog: the main window comes back behind the windows that were in front of it, the front one keeps the keyboard. A portable copy puts its `NSUserDefaults` domain back at Quit, so the open and save panels' `NSNav*` keys no longer stay in `~/Library/Preferences` (`mac/defaults.rs`). `RPAppDelegate` now answers the fallback notification centre's `shouldPresentNotification:`, so banners can show while Rookparcel is in front. The Add dialog's outline no longer builds a folder's whole child list for each child.
- Checked on the VM with real clicks, 1.2.17 against 1.2.19: Add stays in front with Finder in front, with the main window hidden, and both; the plain show/hide toggle is unchanged. The panel's keys were there during a portable run and the domain was identical afterwards (where there was none, an empty plist stays). An Accessibility walk of 30,000 files took 8.5 s, against 9.5 s before. Workspace clippy, the Mac crate for both Apple targets, fmt, the frontend tests (343), the new `swarm` tests, and the full core suite on the engine branch (1,069 passed). **Not checked:** notifications. The VM shows none of the dev app's, in front or behind, so the new delegate was never asked; they stay for the owner's Mac (BACKLOG "macOS" (A)).
