## 2026-11-10_105049_1794304249: Version 1.2.37: lower buttons and fields in the GTK client

- **Reported by the owner:** the GTK client's buttons are very thick beside the Windows and Mac ones; nothing undocumented in the fix.
- **Cause:** the client set no size, so the theme decided: push buttons, entries and drop-downs 34 px high and the toolbar strip 44 px (measured on the Xubuntu VM), against 14 dialog units (about 23 px) on Windows.
- **Fix:** four rules in the application's own stylesheet (`CSS` in `crates/gtk/src/app.rs`), only `min-height`, `min-width` and `padding`: label buttons (`button.text-button`, the class GTK gives them itself), the toolbar's buttons, `entry`/`spinbutton`, and the buttons of drop-downs and menu buttons. Buttons and fields are now 26-28 px and level in a row; the toolbar strip is 36 px. Column headers, check boxes, tabs and the sidebar are untouched; the buttons keep their width.
- **Validation:** before and after pictures on the Xubuntu VM (Xvfb, GTK 4.22, the client's own window snapshots, a mock daemon): the main window, Preferences (General, Connection, Bandwidth), Create New Torrent, RSS Downloader and Add Torrent from URL in GTK's default theme, and the same tour under Greybird. No text or icon is cut, rows stay level, the dialogs are 13-58 px lower. Clippy `-D warnings` for the GTK crate (Linux target, stand-in pkg-config) and fmt. **Not done:** a real desktop session and scaled displays; Add New Torrent, Properties, the search windows and the Setup Guide were not opened; other themes (Yaru, Arc, Breeze) not tried. **Seen, not new:** Create New Torrent logs GTK's "natural size must be >= min size" for a box, before the change too.

## 2026-11-10_103428_1794303268: Version 1.2.36: the Logger without the trackers that do not answer

- **Asked by the owner:** the Logger filled with lines about trackers not answering, which is normal for public trackers; log only when a torrent is private and none of its trackers can connect.
- **Loggers:** the Win32, GTK and shared (`frontend::app`, the Mac) alert loops and the Web UI's `logged` leave `TrackerError` out; the three GUIs also leave `ScrapeFailed` out, as the Web UI already did. Both still show on the Trackers tab, and `rookparcel-nox --verbose` prints them as before.
- **Engine:** `Torrent::trackers_went_silent` is true when a failed announce leaves a private torrent with no tracker that has not failed (the first failure of the last one, not the retries); the engine then posts one `Alert::Log` for the torrent: "the tracker does not answer: ..." or "none of the N trackers answer; the last error: ...". The line has no URL, which holds the passkey. It comes again after a tracker answered, a tracker was added or the torrent was restarted.
- **Decisions:** decided in the engine, which alone knows every tracker's state; an existing alert carries it, so the remote protocol stays 17 (a GUI on an older daemon shows no tracker failures in its Logger). No stored flag: a first try with one grew `Torrent` past the 688 bytes `a_stopped_torrent_stays_compact` allows. A torrent whose private flag is unknown (a magnet before its metadata, a record from before 1.2.30 not yet read) counts as public.
- **Validation:** new test `only_a_private_torrent_without_any_tracker_reports_it`; the core `swarm`, `scrape`, `proxy` and `torrent_properties` suites, nox (84 + 40 + 44 and its integration tests) and frontend (364) pass; clippy `-D warnings` for the workspace on Windows, the GTK crate (Linux target, stand-in pkg-config) and the Mac crate (darwin target); fmt. **Not done:** no end-to-end run of a private torrent against a dead tracker, the Win32 tests were not run (one match arm), and no GUI was looked at. The three oldest entries moved to the archive.

## 2026-11-10_102840_1794302920: Version 1.2.35: Win32 notes that were cut off; an audit of cut-off texts in every language

- **Reported by the owner (screenshot, Hungarian):** Preferences > General, the note "Windows still opens .torrent files with ..." was cut after its second line. The note was a fixed box of two lines beside the Default Apps button; with two ProgIDs it needs three lines in English and four in Hungarian.
- **Fix:** `fit::fit_note_height` makes a note as tall as its wrapped text (never lower than drawn), grows the group box around it and moves the controls below; the General page runs it after each new note text and after `fit_texts`. The Privacy box moves down with it and back when the note empties. Test: `the_integration_note_is_as_tall_as_its_text`.
- **Asked: do others suffer the same?** `tools/win32-shots/capture.ps1` got `-Audit`, `-Language` and `-NoShots`: it measures every visible label, check box, button and group title of each window it opens against the control's size. Run over all 35 tables (every dialog it opens, the Setup Guide, the 12 Preferences pages). Three more places, all fixed:
  - **Preferences > BitTorrent, the IP filter's status** (every language): "Empty: `<path>`" showed only the first word, because a path has no place to wrap. The status now wraps inside words (`SS_EDITCONTROL`) and takes the lines it needs.
  - **Add Torrent from URL's prompt** (German, Bulgarian, Greek): wider than the dialog. `dialogs::input`'s prompt takes a second line and the dialog grows by it (also for New Label, New Profile and the other prompts).
  - **Preferences > Web UI, the note at the bottom** (Greek): five lines in room for four, on the one page with no room to grow. The Greek text is three words shorter (machine translation, like the original).
- **Validation:** the 125 Win32 and 364 frontend tests on one thread, clippy `-D warnings`, fmt. Pictures on the hidden desktop: the General page in Hungarian with a note of two ProgIDs (a temporary build that faked the registry answer, not committed), the German IP filter status and Add URL prompt, the Greek Web UI page; a second audit of Greek, Bulgarian and Hungarian is clean. **Not covered:** the audit sees only what the script opens with a fresh profile, so texts that depend on state (errors, the Web UI's status, Properties of several torrents), message boxes, menus, list columns and 125-200 % are unchecked; it measures in Segoe UI 9 pt; long page names in the Preferences tree are cut by design (tooltip).
