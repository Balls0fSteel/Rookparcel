## 2026-11-07_084750_1794037670: A Docker image of rookparcel-nox, published to GHCR on release tags

- **Owner request:** a Docker image; the owner chose a Dockerfile, a Compose example and docs, plus images for amd64 and arm64 pushed to GitHub's registry on each tag.
- **Image:** `Dockerfile` builds only `rookparcel-nox` (`--locked`, no update check) on `rust:1-bookworm` and runs it on `debian:bookworm-slim` with OpenSSL 3 and the CA certificates, as user `rookparcel` (1000:1000); volumes `/config` (state and settings via `--state-dir`) and `/downloads`, ports 8080 and 6881 TCP/UDP. `contrib/docker/docker-entrypoint.sh` runs nox as PID 1, takes `ROOKPARCEL_WEBUI_PASS`/`_USER` and `UMASK` (0002), and adds options given alone to the default `run`. `contrib/docker/compose.yaml` mounts the media folder at the *arr containers' path and allows 60 s to stop.
- **CI:** `release.yml`'s `docker` job builds each architecture natively (no QEMU) and pushes by digest on a tag; `docker-manifest` tags `ghcr.io/balls0fsteel/rookparcel-nox:<version>` (and `:latest` without a suffix) after the release job. `ci.yml` builds the amd64 image when the Docker files change.
- **Docs:** wiki page `Docker` (run, Compose, password, user ids, Server domains for container names, ports and UPnP), linked from the *arr page, DAEMON.md and README; RELEASING.md has the one-time step of making the package public. No program changed, so no version bump.
- **Validation:** the amd64 image built and ran on the Xubuntu VM (Web UI, temporary and env passwords, state kept across a restart, a clean stop). Not run: the GHCR push, the arm64 image, the workflow itself (BACKLOG "macOS and packaged Linux builds").

## 2026-11-07_084025_1794037225: Version 1.2.21: the Files tab shows the folder tree

- **Owner request:** the Files tab should show the Add Torrent dialog's folder tree, or offer it with a toggle; the owner chose the tree as the default (D62).
- **Shared model:** `FileTree` gains per-file progress with folder sums, engine priorities (`from_entries`, `set_file_states`, shown in µTorrent's three levels so 7/6/5 is not Mixed), `files_under_rows`/`files_under_nodes` and `node_path`; the torrent's own folder is left out but still matched by the filter. `Detail` shows the tree by default, refreshes it in place after a priority change (collapsed folders stay collapsed), and maps every action through `file_indexes`. `ui.files_tree` keeps the choice; strings `FilesTree`, `MenuFilesTree`, `FilesTreeTip` in all 35 tables (machine-translated).
- **Win32:** indents and shell icons (the Add dialog's icon code is now a shared `ShellIcons`), folders open and close by icon click, double click, Enter, Left/Right, +/-; a "Tree view" box left of the filter and a checked menu item; Relocate greyed for folders.
- **GTK:** expander arrows, folder/file icons, Left/Right and double click, a Tree view toggle button and a `win.files-tree` check item. **Fixed:** since the alternate-row shading of 2026-11-05 (in v1.2.0-1.2.20), `table::stripe` freed cells GTK was still building, so the client aborted (or listed no rows) as soon as a torrent was listed on GTK 4.22; it now waits until the cell is in a window.
- **macOS:** an outline with the tab's columns (`table::tree_table`), a Tree view check box and menu item (`Command::FilesTree`); Core adds `set_file_priority_files`, `file_node_path`, `relocate_file_node`.
- **Web UI:** the Add dialog's JS tree is shared with the Files tab: folder sums and Mixed, priorities on folders, collapsed folders kept per torrent, sorting within folders, Left/Right and type-ahead (new for the flat list too); `pa.filesTree` in the browser. The owner set the static-file budget to 500 KB (browsers cache the files); the three files are 252,632 bytes.
- **Validation:** frontend 359 tests, Win32 114, nox (lib 79, `webui` 43 and the rest), GTK 20 and macOS 12 on the VMs; clippy clean for each crate on its platform. Screenshots: Win32 (hidden desktop), GTK (Xvfb), macOS (snapshots), Web UI in the built-in browser at desktop and phone width. Not run: real right-click menus, Open on a folder, RTL, high DPI, Return to open a file in the macOS tree.

## 2026-11-06_232629_1794003989: Version 1.2.20: a file filter and type-ahead in the Add Torrent dialog

- **Owner request:** filter the Add Torrent dialog's files to check or uncheck them quickly, and make a typed letter (G) jump to the files starting with it. The Win32 list never answered `LVN_ODFINDITEMW` (owner-data lists ask their parent), so typed letters did nothing there, nor in the main torrent list and the detail tabs.
- **Shared model:** `FileTree::set_filter` uses D50's rule (every word in the file's path, any case), shows matching files with their folders open, and makes Select All/None, check toggles and folder priority act on the shown files only; folder summaries still count every file. `find_row` and the new `frontend::typeahead` (`find`, `TypeAhead` with a 1 s buffer and same-letter cycling) back type-ahead.
- **Win32:** a filter row above the list (cue "Filter files", the × and "N of M files"; the dialog is 17 DLU taller); Escape empties a filled box instead of closing, Enter goes to the list, Ctrl+F from the list to the box. `controls::answer_find_item` answers `LVN_ODFINDITEMW` in the add list, the main list (Name, in view order), the Files tab (path or file name) and Trackers/Peers/Logger. comctl sends `LVFI_STRING | LVFI_SUBSTRING | LVFI_WRAP` and cycles a repeated letter itself (measured).
- **GTK, macOS, Web UI:** the same filter box and count. GTK type-ahead in the key controller (`scroll_to` FOCUS|SELECT); macOS type-select through `RPTableSource`'s `typeSelectString` methods (add tree and main list), ⌘F to the box; the Web UI list is now keyboard-driven (arrows, Space, letters) and stays under the static-size budget with about 1.4 KB left.
- **Issue:** a failing new Win32 app test hung instead of exiting (the window was still alive while the panic unwound); the test now destroys its window before asserting. Older app tests that assert first can still hang on failure (BACKLOG).
- **Validation:** frontend 359 tests, Win32 113 (one thread, idle), Web UI lib 79 and `webui` 43, fmt clean; clippy `-D warnings` clean for the Win32 and frontend crates, GTK (cross, stand-in pkg-config) and macOS (aarch64, x86_64 check). Hidden-desktop screenshots of the Win32 dialog: "disc" leaves 6 of 10 files with Album open; typing "ex" focuses and selects Extras. The Web UI dialog was driven in the built-in browser (filter, shown-only Select None, Escape, type-ahead). GTK and macOS not run.
