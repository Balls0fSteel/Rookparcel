## 2026-11-10_184543_1794332743: Version 1.2.43: release checks of Statistics, Trackers and Run Program on every client; shell lines refused; nox's stored settings before the engine

- **Asked by the owner:** fix and check what 1.2.42's VM runs left before a release. Four agents in worktrees (Mac, GTK, Win32, nox from a second machine), merged here.
- **Run Program, refused (owner's choice):** a line whose program is a shell told to run a string with a code in it (`cmd ... %N`, PowerShell without `-File`, `sh`/`bash`/... `-c`): such a shell re-reads the name, and `a&calc` ran a second command through `cmd /c` (found by the Win32 run). `run_program::shell_reads_codes`, checked in `split_command`, so the runner never uses one either; naming the script itself is fine. New `RunErrShell` in 35 tables (machine-made). `.bat`/`.cmd` targets are safe through std's escaping, now pinned by a test with 6 hostile names.
- **nox, fixed:** UPnP, NAT-PMP, DHT and LSD switched off in the Web UI were on for the first moments of every start (the engine started with defaults, `webui.json` applied after): `webui::stored_settings` before `Session::start`. Live: with DHT stored off nothing starts. **Web UI:** a session that may not change Run Program no longer reads the lines (empty, as the shim's `autorun_*`); a refusal through a proxy that names no address is logged as one.
- **Mac, fixed:** a refused Trackers or Run Program text was stored once its box went off (`pref_pages::text_error`, asked by `Live::commit`); the multi-line boxes use the fields' 13 pt font, look disabled when off (251 / 45 like the fields), red messages start at their field, Tab leaves Create Torrent's and Properties' boxes (Properties got a key view loop).
- **GTK, fixed:** the Trackers status line follows the page's own box and address (`TrackerList::status_for`): it kept "20 trackers, downloaded ..." beside a box switched off while OK was refused.
- **Checked:** D67 from this PC against nox on the Xubuntu VM: every remote change refused and logged with the PC's address, forwarding headers, Host tricks, LAN and link-local addresses and the shim changed nothing; `--webui-remote-run-program` with the password worked, a .torrent and a magnet ran the program once with whole arguments; the start-up warning. Win32 with a real transfer from a loopback seeder: `.bat` and PowerShell `-File` on added/finished with hostile names, nothing on restart; Update Now with a real https list, the status line over a restart; Statistics over a restart; the three pages and Statistics at 150/200 %, light and dark, audit clean, a live theme flip. GTK: `run.added` once per new torrent, a pasted CRLF list stored as three tiers, a pasted junk line refused, xfwm4 stacking, one Statistics instance, clean exit. Mac (Intel VM, real captures): all fixes in light and dark, Cmd+W on Statistics.
- **Validation:** tests on Windows: frontend (380), nox (all), core's `run_program` (8), Win32 (140, one thread); the Mac crate's 12 on the VM; clippy `-D warnings` for the workspace on Windows, the GTK crate on the VM, the Mac crate for both darwin targets; fmt. **Not done:** Retina and arm64; the Trackers status line with text at 150/200 %; the Win32, Mac and Web UI status lines while the page's box is off (GTK's case); IPv6 from a second machine; the remote GUI protocol.
