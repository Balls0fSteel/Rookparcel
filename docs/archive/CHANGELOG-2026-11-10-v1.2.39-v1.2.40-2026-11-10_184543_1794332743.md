## 2026-11-10_140349_1794315829: Version 1.2.40: trackers added to new downloads, typed or from an https list

- **Asked by the owner:** qBittorrent's "append these trackers" and "append trackers from URL", safely: "what if someone replaces the URL text file with a payload?" (D66).
- **Engine:** `SessionHandle::set_extra_trackers` holds tiers that `add_torrent` appends after a new torrent's own (`Torrent::append_trackers`). Never to a private torrent, a restored one, a duplicate, a `TorrentSource::Resume` import or an add flagged `NO_EXTRA_TRACKERS` (create-and-seed); a magnet carries `EXTRA_TRACKERS_PENDING` (saved as `rp-extra-trackers`) until its metadata shows it is public. The command is not sent over the remote protocol, which stays 18.
- **The list (`frontend::tracker_list`):** typed tiers first, then the fetched ones, 200 at most. The fetch is `https://` only with no downgrade, 256 KiB, and the body is only parsed: UTF-8 without control characters, each line through `is_valid_tracker_url`; a body with more other lines than trackers is refused whole, logged, and the last good list stays (cache `trackers-url.txt`, read through the same checks, dropped when the address changes). Daily, an hour after a failure.
- **Clients:** Preferences > Advanced > Trackers in all four (a new multi-line field kind, Update Now, a status line). The Web UI's four settings need the current password; passwordless sessions and the shim's `setPreferences` cannot change them; a hosted Web UI leaves the page out. nox starts its Web UI before the command line's torrents now, so they get the list; without `--webui` nox has no list.
- **Found on the way:** this engine's seeds do not serve a private torrent's metadata, so a private magnet never completes from them (the private branch of the metadata path has no test). The first page model tidied the typed list before the check, dropping bad lines silently; it now keeps them for the check to refuse.
- **Validation:** new tests: 8 in `tracker_list` (an HTML page, a script with one tracker line, binary, a tampered cache, a non-https address never fetched), 2 engine tests (public, own trackers first, private, opted out, duplicate, restored, a public magnet), a Core test, 5 Win32, 3 nox integration tests (password rule, passwordless sessions, end to end public and private). Suites on Windows: core (929 and its integration tests), frontend (377), nox (202 in all) and Win32 (135, one thread) pass; the Mac crate's 10; clippy `-D warnings` for the workspace on Windows, the GTK crate (Linux target) and the Mac crate (both darwin targets); fmt. The Win32 page pictured in light and dark, English, German and Hungarian, with `-Audit` clean; the Web UI page driven in the built-in browser against a mock daemon (password refusal, a junk line, a failed fetch's status, 375 px, dark). **Not done:** no fetch of a real https list by any client; the GTK and Mac pages never ran (the Mac box applies on leaving it, unchecked); the Win32 status line with text and Enter in the box; 150/200 %; third-party Web UI themes; translations unreviewed (the Bulgarian log line's word order is doubtful).

## 2026-11-10_133253_1794313973: Version 1.2.39: Help > Statistics, with all-time totals that outlive the torrents

- **Asked by the owner:** statistics tracking, as qBittorrent has (D65). First of three features planned together; auto-appended trackers (1.2.40) and Run Program (1.2.41) follow.
- **Engine:** `engine/lifetime.rs` keeps the payload bytes of every session in `stats.dat` beside `resume.db` and adds the running session's counters on top, so removing a torrent takes nothing away. Written in the resume-save cycle (30 s while something moved, and at exit) through a temporary file and a rename. A first start without the file begins from the sum of the saved torrents' totals; an unreadable file starts again with one Logger line. `SessionStats` gained `alltime_upload`, `alltime_download`, `alltime_since` and `wasted_bytes` (failed pieces and unrequested blocks, this session): **remote protocol 18**.
- **Clients:** `frontend::statistics::rows` gives the same 14 lines everywhere (All Time, This Session, Disk). Win32: a modeless window from Help > Statistics, dark in dark mode. GTK and Mac: small windows refreshed each second. Web UI: a Statistics button and dialog fed by `GET /pa/session/stats`. qBittorrent API: `alltime_dl`, `alltime_ul`, `global_ratio`, `total_wasted_session`, `read_cache_hits` in `server_state`.
- **Decisions:** payload only (qBittorrent's all-time figures include protocol overhead and drift from its per-torrent sums); no reset button; waste is per session. `Request::Refused` boxes its alert, since the larger `SessionStats` tripped clippy's `large_enum_variant`. Nine new strings in all 35 tables (machine-made translations).
- **Validation:** new tests: four in `lifetime.rs`, three in `frontend::statistics`, five in the Win32 window, two in nox; the swarm restart test now checks the totals after a restart and after the torrent's removal. Suites on Windows: core (929 and its integration tests), frontend (367), nox (86 + 40 + 44 and the rest) and Win32 on one thread pass; the Mac crate's 10 tests; clippy `-D warnings` for the workspace on Windows, the GTK crate (Linux target, stand-in pkg-config) and the Mac crate (both darwin targets); fmt. Win32 window pictured on the hidden desktop in light and dark (English, `--demo`). Web UI dialog opened in the built-in browser against a mock daemon: desktop dark, 375 px light, polling stops on Close. **Not done:** the GTK and Mac windows were only compiled and linted for their targets, never run; no translation was seen in a window; the Win32 window at 150/200 % and in right-to-left; the nine Web UI themes one by one; a real transfer through a GUI. The three oldest entries moved to the archive.
