## 2026-11-17_092503_1794903903: Version 1.2.64: peers again after a file is turned on; Files tab sort; a visible unfocused selection (D78)

- **"Downloading" with no peers after turning a file on (owner):** two delays, both reproduced. The seeds `on_finished` closed as redundant were stamped as just connected, so each waited out `min_reconnect_time` (60 s, longer after failures) before it was a candidate again; libtorrent 2.0's `resume_download` has the same gap. And nothing re-announced: the next tracker announce could be an interval (about 30 min) away, asked with `numwant` 0 when the torrent had many peers. A theory that trackers saw left=0 was ruled out (a skipped file keeps left above 0). New `Engine::resume_download` for the finished-to-downloading change: reaps pending closes, forgets every known peer's last connection (as on leaving upload mode), asks each tracker again as soon as its `min interval` allows (`TrackerEntry::announce_soon`, not for failing or busy trackers; event none), prompts the DHT and LSD and connects at once. A stopped torrent that becomes unfinished now asks for an auto-manage pass. New swarm tests (reconnect with a 3,600 s reconnect delay; a re-announce with left>0 that finds a seed only the tracker knows) failed before and pass; the old skip test lost its second-seed workaround. Wire format unchanged, so `PEER_ID_PREFIX` stays. Still as in libtorrent: Force Re-Check and pause/resume leave peers in the 60 s delay.
- **Files tab sort (Win32, owner):** header clicks sort by any column (names, sizes and pieces ascending first; Done, % and Priority descending first), a second click reverses, a third returns to the torrent's order; the tree sorts each folder, folders first; kept as `ui.files_sort`. Rows moved by progress or priorities keep their selection. The owner's offer of a limit or a progress dialog was measured away: 100,000 files sort in 1-66 ms in a release build (`sorting_a_hundred_thousand_files`, ignored by default). GTK and macOS sort no detail table yet (BACKLOG); the Web UI already sorted Files.
- **Unfocused selection (Win32, owner):** after Alt+Tab a selected row was drawn in the button face (0xF0F0F0), one step from the shaded rows (0xEFEFEF), so it vanished on them. Now the highlight mixed into the window colour (30 % light, 70 % dark) under the window's text; High Contrast keeps the highlight. Pictured light and dark on the hidden desktop.
- **Validation:** frontend 451 tests, Win32 172 (one thread), core lib and every core test binary (swarm 62), clippy and rustfmt clean on the changed crates.
