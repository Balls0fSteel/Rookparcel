## 2026-11-19_161259_1795101179: 1.2.70's benchmark again, on a self-deleting Hetzner server

- **On the owner's word** (Hetzner with dedicated AMD for the SHA extensions, a Storage Box for the results, self-delete "so we don't lose any money", "Yes, CCX23"): `tools/bench/cloud/launch-hetzner.ps1` and `finish-hetzner.sh` (`78df2990`). The project's main token stays on this PC; only the bench token goes to the server, over SSH into a root-only file. A Storage Box subaccount takes the results over WebDAV; a `systemd-run` timer is the deadline. The CX23 self-test (about €0.01) uploaded, then deleted its key and itself.
- **The run:** CCX23 (4 dedicated AMD EPYC Milan vCPUs with SHA-NI, 16 GB, fsn1), `main` at `d28b2220` (the engine of `52f0eda3`) against `v1.2.69`, 10:04-13:34 Budapest time, all 66 runs exit 0; raw results in `docs/benchmarks/`, written up in BENCHMARKS.md. Idle CPU as 1.2.69's at one-tick resolution (both idle windows at 10,000: 15 ticks against 14); the DigitalOcean run's 10,000-listing delay did not reproduce (0.22-0.23 s for both); with SHA-NI Rookparcel's download used the least CPU of the five (1.89 s per GiB, 0.74 times qBittorrent's against 1.86 times on the Xeon), which strengthens the SHA-1 suspect. BACKLOG updated.
- **Problem: the server ran until its 6 h deadline (16:01), 2.5 h after `ALL DONE`.** `run.sh` runs as `bench` and tested `[ -x ]` on `bench-finish`, installed mode 700 for root: false for `bench`, so the finish was skipped without a word. The self-test had called it as root and passed. The deadline worked (upload, key and server deleted; the API lists 0 servers and 0 keys). Cost about €1.05 instead of about €0.62, estimated from the hourly price.
- **Fix:** `run.sh` asks `sudo -n test -x` and logs `bench-finish exit N`; `run.sh --finish` runs only that step and `setup.sh --user-only` only creates `bench`, so `-SelfTest` now calls the finish as `bench` through sudo, as a real run does; a real launch warns when `bench` cannot run it. On the Xubuntu VM with a root-only stub: the old guard skips it, the new path reaches it as root, the self-test's command chain passes; test user and stub removed. On Hetzner the same evening the CX23 self-test passed with it: `bench-finish exit 0` as `bench`, reason `done`, 0 servers and 0 keys left. ## 2026-11-19_093640_1795077400: 1.2.70's benchmark on a rented server

- **On the owner's word** (a DigitalOcean API token on their PC, "do a full run, just delete VM after"; the token stayed on the PC: API calls from a local script only).
- **Run:** a `c-4` droplet (4 dedicated vCPUs, Xeon Platinum 8280, 8 GB, Ubuntu 26.04, `ams3`), the full `bench.py` set with 1.2.69 as `--control`, both built on the server with the release command; 3 h 38 min, all 66 runs finished. Results in BENCHMARKS.md "Release check, 2026-11-18" and `docs/benchmarks/2026-11-18-digitalocean-c4-1.2.70.jsonl`; the website is unchanged (not published builds, another machine).
- **Outcome:** the round-robin connect loop costs no measurable idle CPU (1,000: 0.03 % both; 10,000: 0.07 against 0.05, one clock tick, same ranges). New in BACKLOG "Disk and storage": Rookparcel's download costs twice the other clients' CPU on a CPU without SHA-NI (portable SHA-1 suspected), and 10,000 torrents listed 0.04 s later after a restart.
- **`tools/bench/cloud/`** (`setup.sh`, `build.sh`, `run.sh`) and BENCHMARKS.md "Running it on a rented machine" make the run repeatable on any fresh Ubuntu 26.04 server.
- **Problem:** the local guard that was to delete the droplet at 04:06 most likely ended with the owner's Windows session (the wait loop's last error, at 23:53, was `0xC000026B`, a DLL init failed at logoff), so the droplet ran about 12.5 h instead of 4: about $1.60 instead of under $1. Deleted at 09:35 with its SSH key, both listings checked. A guard on the PC cannot outlive a logoff or shutdown; the next run's wait loop deletes the server itself as soon as the results are copied.
