**Rookparcel 1.2.45** stops the program from pausing your seeds by itself. Until now every torrent was stopped once it had uploaded one and a half times its size, whether you had asked for that or not, and starting it again stopped it again a second later. Seeds now run until you stop them, unless you switch a seeding goal on.

Rookparcel is a lean BitTorrent client in the spirit of µTorrent 2.2.1: small single-file binaries, a native look, low RAM and CPU use, and an interface that stays responsive with tens of thousands of torrents. The engine is our own Rust port of libtorrent-rasterbar 2.0.11; nothing is linked.

## New since 1.2.44

- **Seeds are no longer stopped at a ratio of 1.5 by default.** Preferences > Queueing has a seeding goal of 150 %, as µTorrent does. In µTorrent that number does nothing until "Limit the upload rate to (kB/s): [0: stop]" is ticked; Rookparcel stopped every queued torrent that reached it. Now it is as in µTorrent: with the box off, as it is at first, torrents seed on. Tick the box with 0 to stop torrents at the goal, or with a rate to let them seed on slowly.
- **Your settings on update.** If you never changed the goal (150 %, no minimum time), it is switched off: nothing is stopped any more. If you had set a goal of your own, it stays in force: the box is ticked for you, with 0. Torrents that were stopped before the update stay stopped until you start them.
- **A torrent you start again keeps seeding.** A goal acts on a torrent once. When a goal has stopped a torrent and you start it again, it seeds until you stop it. It is stopped again only after you change the goal and the torrent reaches the new one.
- **The Logger says why a torrent was stopped.** The line names what was reached, for example "seeding goal reached, stopped (ratio 1.523, goal 1.500)", with the seeding time when a time goal is set.
- **A torrent's own goal is always in force.** A goal set in Properties, sent by Sonarr or Radarr with a download, or imported from qBittorrent stops its torrent as before, also while the box in Preferences is off.
- **Web UI.** The Queueing page's box reads "Stop the torrent or limit its upload rate". The qBittorrent-compatible API reports the global share limit as enabled only when the goal is switched on and stops torrents.
- On Windows, Linux, macOS and in `rookparcel-nox`.

## Updating

- **Windows installer.** Rookparcel 1.2.5 and later offer the update themselves: Help > Check for Updates, then "Download and install". Settings and torrents are kept.
- **macOS.** Quit Rookparcel first, then drag the new `Rookparcel.app` to Applications over the old one.
- **Everything else.** Replace the program, the AppImage or the bundle as before. Settings and torrents are kept.
- **Seeding goal.** See "Your settings on update" above. To keep stopping torrents at 150 %, tick "Limit the upload rate to (kB/s): [0: stop]" in Preferences > Queueing and leave the rate at 0.
- **Sonarr and Radarr with the global limit.** If the apps relied on the client's default 150 % to know when a download may be removed, switch the goal on as above, or set a seed ratio in the app's indexer settings: that one travels with each download and always applies.
- **Remote control.** 1.2.44 and 1.2.45 speak the same remote protocol (18). Versions before 1.2.44 do not connect to either.
- **From PaTorrent.** PaTorrent does not offer this update. Install Rookparcel by hand, as in [1.2.5's notes](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.45/docs/releases/1.2.5.md#coming-from-patorrent).

## First run

The website's [install guide](https://balls0fsteel.github.io/Rookparcel/install.html) shows these steps one at a time.

- **Windows installer.** Run the setup. It is not code-signed, so SmartScreen shows "Windows protected your PC": click More info > Run anyway. "Install for anyone using this computer" asks for administrator rights and shows "Unknown publisher". Settings and torrents are in `%APPDATA%\Rookparcel`.
- **Windows zip.** Unzip anywhere and start `rookparcel.exe`; SmartScreen warns as above. An empty `rookparcel.ini` next to the exe keeps settings and torrents beside it (portable mode).
- **macOS.**
  1. Open the disk image and drag `Rookparcel.app` to Applications.
  2. The app is ad-hoc signed and not notarised, so Gatekeeper refuses it the first time. The disk image's `How to open Rookparcel.html` has these steps too.
     - macOS 15 Sequoia and newer: double-click the app and click Done in the warning. Open System Settings > Privacy & Security, scroll to Security and click Open Anyway (offered for about an hour), then confirm with your password or Touch ID.
     - macOS 11 to 14: Control-click (or right-click) the app, choose Open, then click Open.
     - Or, also when macOS says the app "is damaged", run `xattr -dr com.apple.quarantine /Applications/Rookparcel.app` in Terminal.
  3. macOS may ask whether Rookparcel may find devices on local networks. Allow it for peers and a Rookparcel daemon on your own network; downloads from the internet work either way.

  Settings and torrents are in `~/Library/Application Support/Rookparcel/mac`.
- **Linux AppImage.** Run `chmod +x Rookparcel-1.2.45-x86_64.AppImage`, then start it. Without FUSE 2 on the system, start it with `--appimage-extract-and-run`. Settings are in `~/.config/rookparcel/gtk`, torrents in `~/.local/share/rookparcel/gtk`.
- **Linux Flatpak.** The bundle holds the application; the runtime comes from Flathub:

  ```bash
  flatpak remote-add --if-not-exists --user flathub https://dl.flathub.org/repo/flathub.flatpakrepo
  flatpak install --user Rookparcel-1.2.45-x86_64.flatpak
  flatpak run io.github.balls0fsteel.Rookparcel
  ```

- **Headless.** `rookparcel-nox run --webui 8080 --webui-pass PASS` starts the daemon with its Web UI and a qBittorrent-compatible Web API on port 8080. [DAEMON.md](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.45/docs/DAEMON.md) describes services: systemd, FreeBSD rc.d, `--daemon` and Windows, one per profile if you like. Your own Web UI themes go in `webui/themes` under its settings folder (`/config` in Docker).
- **Docker.**

  ```bash
  docker run -d --name rookparcel -p 8080:8080 -p 6881:6881 -p 6881:6881/udp -e ROOKPARCEL_WEBUI_PASS=choose-one -v rookparcel-config:/config -v /srv/media:/downloads ghcr.io/balls0fsteel/rookparcel-nox:1.2.45
  ```

  Then open `http://<host>:8080` and log in as `admin`. Without `ROOKPARCEL_WEBUI_PASS`, `docker logs rookparcel` shows a temporary password. Stop it with `docker stop -t 60 rookparcel`, so it has time to save its torrents.

## Known limitations

- **Not tried by hand.** The change ran in automated tests on Windows; the Linux and Mac programs were only compiled and checked for errors, and no updated real profile was run before the release.
- **"When Everything Completes" in Auto Shutdown waits for seeds to stop.** With no goal in force, seeds never stop by themselves, so that choice waits for ever: switch a goal on first, or choose a "When Downloads Complete" item.
- **The three new texts are machine-translated** in the languages other than English.
- Everything in [1.2.0's limitations](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.45/docs/releases/1.2.0.md#known-limitations), [1.2.5's](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.45/docs/releases/1.2.5.md#known-limitations), [1.2.19's](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.45/docs/releases/1.2.19.md#known-limitations), [1.2.21's](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.45/docs/releases/1.2.21.md#known-limitations), [1.2.30's](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.45/docs/releases/1.2.30.md#known-limitations) and [1.2.44's](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.45/docs/releases/1.2.44.md#known-limitations) still applies.
- **Do not use it on private trackers yet.** The client ID `RP` is not whitelisted anywhere.
