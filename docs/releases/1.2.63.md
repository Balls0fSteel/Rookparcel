**Rookparcel 1.2.63** brings tags, download order for previewing a video, `.!ut` names for unfinished files, files left out by name, a block list kept current from a web address, and a settings page for the window lock. It covers the development versions 1.2.58 to 1.2.62, and fixes what the security review of those versions found.

Rookparcel is a lean BitTorrent client in the spirit of µTorrent 2.2.1: small single-file binaries, a native look, low RAM and CPU use, and an interface that stays responsive with tens of thousands of torrents. The engine is our own Rust port of libtorrent-rasterbar 2.0.11; nothing is linked.

## New since 1.2.57

- **Tags.** A torrent keeps its one label and can have any number of tags besides it, as in qBittorrent. Torrent menu > **Tags** gives and takes them (**New Tag...**, **Remove All Tags**, then each tag, ticked when every selected torrent has it). The category list has a **Tags** group under the labels, with counts and **No Tag**; right-click it for **New Tag...** or a tag for **Delete Tag**. A **Tags** column can be shown in the torrent list.
  - The qBittorrent-compatible Web API has the tag calls, so an app that sets tags through it keeps them. Before, tags were accepted and dropped.
  - A qBittorrent import brings its tags over as tags. Before, a torrent without a category took its first tag as its label.
- **Download order** (Torrent menu > Advanced, the Add New Torrent window and Properties):
  - **Download in Sequential Order** gets the pieces from the start of the data to its end, so a player can play a video as it arrives.
  - **Download First and Last Pieces First** gets the start and the end of each wanted file early, which most players need before they can open it.
  - Both cost the swarm: leave them off for torrents you are not watching. The wiki's [Managing torrents](https://github.com/Balls0fSteel/Rookparcel/wiki/Managing-torrents#download-order) page explains when they help.
- **Copy Magnet Link and Export .torrent...** in the torrent menu: the selected torrents' magnet links on the clipboard, one per line, or their `.torrent` files saved where you choose. A magnet link holds the trackers, so do not share one copied from a private tracker's torrent: its address usually holds your passkey.
- **Append .!ut to incomplete files** (Preferences > General > When Downloading, off by default). A file still downloading is stored as `name.!ut` and gets its real name once all of it has passed its check, so a player or Sonarr and Radarr never pick up half a file. Turning it on or off renames running torrents' files at once.
  - **Partial files from µTorrent and qBittorrent are used** whether the box is ticked or not. A file missing under its name is looked for as `name.!ut` and `name.!qB`, so an imported torrent, or one added again into its old folder, carries on instead of starting over.
  - A crash between a rename and the next save heals at the next start, without a recheck. An existing file is never overwritten, and **Remove And > Delete Data** deletes a `.!ut` or `.!qB` file only when it holds the torrent's data. The wiki's [Disk and storage](https://github.com/Balls0fSteel/Rookparcel/wiki/Disk-and-storage#incomplete-files-and-ut) page has the details.
- **Files left out by name** (Preferences > UI Settings > When Adding Torrents > **Do not download files named:**). Files matching a pattern such as `*.lnk; *sample*; Thumbs.db` are unticked when a torrent is added, also for magnets, RSS, auto-load and Sonarr and Radarr. You can still tick them in the Add New Torrent window or on the Files tab.
- **The IP filter's block list from a web address** (Preferences > BitTorrent > IP filter > **Get the block list from this address (https):**). Rookparcel downloads it once a day, plain or gzip-compressed, keeps the last good copy and puts it in force at the next start before downloading anything. A failed download keeps the rules already in force.
  - **CIDR lines** (`10.0.0.0/8`, IPv4 and IPv6) are read beside the `ipfilter.dat` and PeerGuardian P2P formats, in a file on your computer too.
- **Preferences > Advanced > UI Lock.** The window lock of 1.2.54 has its own page: **Allow locking Rookparcel with a PIN**, and Set, Change and Remove PIN. With the box unticked, File > Lock, Ctrl+L and the tray's Lock are gone. The page acts at once, without OK. Options > Lock PIN is gone.
  - On Windows the Set PIN window is a quarter narrower, and its message line grows only when a message needs it.
- **Fixes from this release's security review** (the review's other findings were in the new features above and were fixed before they shipped):
  - While locked, the Windows program opens no right-click menu but the tray's, and the Linux program also refuses actions that another program sends it over D-Bus.
  - `rookparcel-nox`: the Web UI's Preferences page no longer receives the tracker list's address with a user name or password in it.
  - A web server's reply text and redirect address reach the Logger and the status lines shortened and without control characters.
- **Windows: a crash in dark mode** about three seconds after pointing at a menu item without help text (a label's or a profile's name) is fixed.
- On Windows, Linux, macOS and in `rookparcel-nox` with its Web UI.

## Updating

- **Windows installer.** Rookparcel 1.2.5 and later offer the update themselves: Help > Check for Updates, then "Download and install". Settings and torrents are kept.
- **macOS.** Quit Rookparcel first, then drag the new `Rookparcel.app` to Applications over the old one.
- **Everything else.** Replace the program, the AppImage or the bundle as before. Settings and torrents are kept.
- **The settings check of 1.2.57** finds nothing to hold for an update from 1.2.57: the new settings are added at their defaults.
- **The lock PIN.** A PIN set in 1.2.54 or 1.2.57 is kept, and the new **Allow locking Rookparcel with a PIN** box starts ticked.
- **Remote control.** The remote protocol is now 20: a window and the `rookparcel-nox` it drives must both be 1.2.63. 1.2.55 to 1.2.57 speak 19 and do not connect to 1.2.63.
- **Going back to an older version.**
  - **With Append .!ut ticked, untick it first** and let the files be renamed: 1.2.57 and older do not know the `.!ut` names and download those files again under their plain names. Running torrents' files are renamed at once, stopped torrents' only when they next start, so start those once too.
  - 1.2.57 and older do not know the tags, the download order switches, the excluded names or the block list's address.
  - 1.2.57 and older have Options > Lock PIN again; turning the lock off in 1.2.63 removed the PIN.
- **From before 1.2.45.** The seeding goal changed in 1.2.45: see [its notes](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.63/docs/releases/1.2.45.md#updating).
- **From PaTorrent.** PaTorrent does not offer this update. Install Rookparcel by hand, as in [1.2.5's notes](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.63/docs/releases/1.2.5.md#coming-from-patorrent).

## First run

The website's [install guide](https://balls0fsteel.github.io/Rookparcel/install.html) shows these steps one at a time.

- **Windows installer.** Run the setup. It is not code-signed, so SmartScreen shows "Windows protected your PC": click More info > Run anyway. "Install for anyone using this computer" asks for administrator rights and shows "Unknown publisher". Settings and torrents are in `%APPDATA%\Rookparcel`.
- **Windows zip.** Unzip anywhere and start `rookparcel.exe`; SmartScreen warns as above. An empty `rookparcel.ini` next to the exe keeps settings and torrents beside it (portable mode).
- **macOS.**
  1. Open the disk image and drag `Rookparcel.app` to Applications.
  2. The app is ad-hoc signed and not notarised, so Gatekeeper refuses it the first time. The disk image's `How to open Rookparcel.html` has these steps too.
     - macOS 15 Sequoia and newer: double-click the app and click Done in the warning. Open System Settings > Privacy & Security, scroll to Security and click Open Anyway (offered for about an hour), then confirm with your password or Touch ID.
     - macOS 11 to 14: Control-click (or right-click) the app, choose Open, then click Open.
     - Or, also when macOS says the app "is damaged", run `xattr -dr com.apple.quarantine /Applications/Rookparcel.app` in Terminal.
  3. macOS may ask whether Rookparcel may find devices on local networks. Allow it for peers and a Rookparcel daemon on your own network; downloads from the internet work either way.

  Settings and torrents are in `~/Library/Application Support/Rookparcel/mac`.
- **Linux AppImage.** Run `chmod +x Rookparcel-1.2.63-x86_64.AppImage`, then start it. Without FUSE 2 on the system, start it with `--appimage-extract-and-run`. Settings are in `~/.config/rookparcel/gtk`, torrents in `~/.local/share/rookparcel/gtk`.
- **Linux Flatpak.** The bundle holds the application; the runtime comes from Flathub:

  ```bash
  flatpak remote-add --if-not-exists --user flathub https://dl.flathub.org/repo/flathub.flatpakrepo
  flatpak install --user Rookparcel-1.2.63-x86_64.flatpak
  flatpak run io.github.balls0fsteel.Rookparcel
  ```

- **Headless.** `rookparcel-nox run --webui 8080 --webui-pass PASS` starts the daemon with its Web UI and a qBittorrent-compatible Web API on port 8080. [DAEMON.md](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.63/docs/DAEMON.md) describes services: systemd, FreeBSD rc.d, `--daemon` and Windows, one per profile if you like. Your own Web UI themes go in `webui/themes` under its settings folder (`/config` in Docker).
- **Docker.**

  ```bash
  docker run -d --name rookparcel -p 8080:8080 -p 6881:6881 -p 6881:6881/udp -e ROOKPARCEL_WEBUI_PASS=choose-one -v rookparcel-config:/config -v /srv/media:/downloads ghcr.io/balls0fsteel/rookparcel-nox:1.2.63
  ```

  Then open `http://<host>:8080` and log in as `admin`. Without `ROOKPARCEL_WEBUI_PASS`, `docker logs rookparcel` shows a temporary password. Stop it with `docker stop -t 60 rookparcel`, so it has time to save its torrents.

## Known limitations

- **What was tried.** Unit and integration tests on Windows, Linux, macOS and FreeBSD. Each feature was tried in the Windows program on a hidden desktop, in the Linux program on a virtual machine and in the Mac app on a macOS virtual machine. `.!ut` with real downloads: 1.37 GB through `rookparcel-nox` on Windows with a hard kill and restart, 461 MiB in the Linux program with a hard kill, 100 MB in the Mac app. Real Sonarr and Radarr grabbed through the daemon; neither version sends tags, so their tag call was replayed by hand. The security review's fixes were checked by tests, not run again by hand. Not tried by hand: Copy Magnet Link and the Save dialogs in the Windows program, the Web UI's Copy and Export in a real browser, a block list downloaded by the Windows or the Mac program. The release files were not started on a desktop before publishing.
- **The new texts are machine translations** in every language but English.
- **A block list is trusted as it is.** A list that blocks every address is accepted. With a new address there is no block list in force until its first download arrives.
- **A tag made in a window and one made in a browser within the same second** in a Windows program that hosts the Web UI can lose one of the two.
- **Downloaded files carry no "downloaded from the internet" mark** (Mark of the Web, macOS quarantine), and Open asks nothing before opening an unfinished or executable file.
- **A µTorrent or qBittorrent partial file that was picked up but never checked** is kept on Remove And > Delete Data: delete it by hand.
- Everything in [1.2.0's limitations](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.63/docs/releases/1.2.0.md#known-limitations), [1.2.5's](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.63/docs/releases/1.2.5.md#known-limitations), [1.2.19's](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.63/docs/releases/1.2.19.md#known-limitations), [1.2.21's](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.63/docs/releases/1.2.21.md#known-limitations), [1.2.30's](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.63/docs/releases/1.2.30.md#known-limitations), [1.2.44's](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.63/docs/releases/1.2.44.md#known-limitations), [1.2.45's](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.63/docs/releases/1.2.45.md#known-limitations), [1.2.46's](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.63/docs/releases/1.2.46.md#known-limitations), [1.2.54's](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.63/docs/releases/1.2.54.md#known-limitations), [1.2.57's](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.63/docs/releases/1.2.57.md#known-limitations) still applies.
- **Do not use it on private trackers yet.** The client ID `RP` is not whitelisted anywhere.

## Reporting problems

Open an [issue](https://github.com/Balls0fSteel/Rookparcel/issues) with your platform, the file you used and what happened. For a crash or a stuck torrent, include the Logger tab or `rookparcel-nox run --verbose` output. On a Mac, Console.app's crash report for Rookparcel helps too. For security problems, see [SECURITY.md](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.63/SECURITY.md).
