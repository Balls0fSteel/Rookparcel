**Rookparcel 1.2.76** keeps the pieces of a torrent whose drive or share has gone: it holds the torrent with "files missing" and starts it again by itself when the storage is back, instead of downloading everything again. Force Re-Check now starts a stopped torrent, and the release carries the fixes of a full review of the code.

Rookparcel is a lean BitTorrent client in the spirit of µTorrent 2.2.1: small single-file binaries, a native look, low RAM and CPU use, and an interface that stays responsive with tens of thousands of torrents. The engine is our own Rust port of libtorrent-rasterbar 2.0.11; nothing is linked.

## New since 1.2.69

This release also covers the development versions 1.2.70 to 1.2.75.

- **A missing drive or share no longer means downloading again.** When none of a torrent's files is found (a USB disk pulled, a network share or a mount not there, a drive letter not ready yet), the torrent stops with "files missing (the drive, share or folder is not available)" and keeps the pieces it had, across restarts too. Every 30 seconds Rookparcel looks whether the storage is back; when it is, the torrent starts and finds its files without hashing them. A drive pulled while a torrent downloads is held the same way.
  - One file of several deleted still loses only its own pieces, as before.
  - Start tries again at once (and holds the torrent again if the files are still missing). Force Re-Check accepts what is on disk and downloads the rest.
- **Force Re-Check starts a stopped torrent.** Before, a stopped torrent only forgot its pieces and the check waited until you pressed Start. Now the check runs at once and the torrent starts after it; stop it again if you like. A queued torrent is checked at once too and queued again after. The qBittorrent-compatible API's `torrents/recheck` keeps qBittorrent's behaviour, so Sonarr and Radarr see no change.
- **"Queued for checking".** A check waiting for its drive (one check per drive at a time) said "Checking 0.0 %"; it now says it is queued, in all programs and the Web UI.
- **A check that cannot read a file stops the torrent** with the error, instead of taking the file as empty and downloading it again (a file another program holds open, or one without permission).
- **Connections are shared fairly between torrents.** Each torrent gets its turn at new peer connections, downloads first, so a torrent late in the list no longer waits for peers indefinitely.
- **From the code review of 1.2.70** (34 findings; all fixed or decided):
  - *Security.* Piece layers shipped in a v2 `.torrent` are checked against its file hashes. The remote connection a window uses to drive `rookparcel-nox` can no longer add a torrent from resume data or rename files out of the save folder, so `--webui-save-root` holds. An RSS feed's links reach your local network only when the feed itself came from it. A wrong current password counts towards the Web UI's login ban.
  - *Engine.* Turning the DHT on or off applies at once. A peer banned for bad data cannot connect again from another port. End-game asks for duplicate blocks only at the very end (many small files finish much faster). A tracker answer that arrives after a stop no longer holds up the next start. A late DNS answer cannot steer another tracker request. A finished hybrid torrent reports completion under both its hashes. UPnP frees the slots of mappings it deleted.
  - *Data.* A failed write of `resume.log` (a full disk) is repaired at the next save instead of leaving a torn entry. A piece finished during a stop is no longer counted twice. An RSS smart filter tries an episode again when its download failed, and version numbers such as `Ubuntu 22.04` are no longer taken for episodes.
  - *From this release's own review.* Peers banned for bad data no longer stay in a torrent's peer list (their addresses stay banned), so peers banned from many addresses cannot fill the list and keep new peers out. A stopped recheck gives its queue slot back. The Run Program check also knows `script`, `expect`, `forfiles`, `wmic`, editors and debuggers that run a string as code.
  - *Programs.* The Run Program check refuses more ways of running a torrent's name as code (wrappers, interpreters, `find -exec`). The Web UI closes its dialogs when a session ends and keeps a queued `.torrent` for after the login. Windows: Preferences applies the other settings before restarting the Web UI; a second start while the window closes runs on its own. Linux: dialogs wait for the window lock's PIN, and a vanished tray icon asks for it. macOS: no Auto Layout warnings at start.

## Updating

- **Windows installer.** Rookparcel 1.2.5 and later offer the update themselves: Help > Check for Updates, then "Download and install". Settings and torrents are kept.
- **macOS.** Quit Rookparcel first, then drag the new `Rookparcel.app` to Applications over the old one.
- **Everything else.** Replace the program, the AppImage or the bundle as before. Settings and torrents are kept.
- **The settings check of 1.2.57** finds nothing to hold for an update from 1.2.69.
- **Remote control: update both ends.** The remote protocol is now 21: a window and the `rookparcel-nox` it drives must both be 1.2.76. 1.2.63 to 1.2.69 speak 20 and do not connect to it. The Web UI and the qBittorrent-compatible API are not affected.
- **Torrents that already downloaded again.** A torrent that lost its pieces to a missing drive under an older version has saved that; this release cannot bring them back. If its files are on the drive again, Force Re-Check finds them.
- **A v2 `.torrent` with wrong piece layers** now stops with an error, where older versions took it; a v2-only torrent whose stored layers fail fetches them from peers and checks its files once.
- **Going back to 1.2.69** needs nothing for the settings or the torrents; a held torrent then downloads its files again as before.
- **From before 1.2.63.** Read [1.2.63's notes](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.76/docs/releases/1.2.63.md#updating) too: going back below 1.2.63 with Append .!ut ticked needs it unticked first.
- **From before 1.2.45.** The seeding goal changed in 1.2.45: see [its notes](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.76/docs/releases/1.2.45.md#updating).
- **From PaTorrent.** PaTorrent does not offer this update. Install Rookparcel by hand, as in [1.2.5's notes](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.76/docs/releases/1.2.5.md#coming-from-patorrent).

## First run

The website's [install guide](https://balls0fsteel.github.io/Rookparcel/install.html) shows these steps one at a time.

- **Windows installer.** Run the setup. It is not code-signed, so SmartScreen shows "Windows protected your PC": click More info > Run anyway. "Install for anyone using this computer" asks for administrator rights and shows "Unknown publisher". Settings and torrents are in `%APPDATA%\Rookparcel`.
- **Windows zip.** Unzip anywhere and start `rookparcel.exe`; SmartScreen warns as above. An empty `rookparcel.ini` next to the exe keeps settings and torrents beside it (portable mode).
- **macOS.**
  1. Open the disk image and drag `Rookparcel.app` to Applications.
  2. The app is ad-hoc signed and not notarised, so Gatekeeper refuses it the first time. The disk image's `How to open Rookparcel.html` has these steps too.
     - macOS 15 Sequoia and newer: double-click the app and click Done in the warning. Open System Settings > Privacy & Security, scroll to Security and click Open Anyway (offered for about an hour), then confirm with your password or Touch ID.
     - macOS 11 to 14: Control-click (or right-click) the app, choose Open, then click Open.
     - Or, also when macOS says the app "is damaged", run `xattr -dr com.apple.quarantine /Applications/Rookparcel.app` in Terminal.
  3. macOS may ask whether Rookparcel may find devices on local networks. Allow it for peers and a Rookparcel daemon on your own network; downloads from the internet work either way.

  Settings and torrents are in `~/Library/Application Support/Rookparcel/mac`.
- **Linux AppImage.** Run `chmod +x Rookparcel-1.2.76-x86_64.AppImage`, then start it. Without FUSE 2 on the system, start it with `--appimage-extract-and-run`. Settings are in `~/.config/rookparcel/gtk`, torrents in `~/.local/share/rookparcel/gtk`.
- **Linux Flatpak.** The bundle holds the application; the runtime comes from Flathub:

  ```bash
  flatpak remote-add --if-not-exists --user flathub https://dl.flathub.org/repo/flathub.flatpakrepo
  flatpak install --user Rookparcel-1.2.76-x86_64.flatpak
  flatpak run io.github.balls0fsteel.Rookparcel
  ```

- **Headless.** `rookparcel-nox run --webui 8080 --webui-pass PASS` starts the daemon with its Web UI and a qBittorrent-compatible Web API on port 8080. [DAEMON.md](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.76/docs/DAEMON.md) describes services: systemd, FreeBSD rc.d, `--daemon` and Windows, one per profile if you like. Your own Web UI themes go in `webui/themes` under its settings folder (`/config` in Docker).
- **Docker.**

  ```bash
  docker run -d --name rookparcel -p 8080:8080 -p 6881:6881 -p 6881:6881/udp -e ROOKPARCEL_WEBUI_PASS=choose-one -v rookparcel-config:/config -v /srv/media:/downloads ghcr.io/balls0fsteel/rookparcel-nox:1.2.76
  ```

  Then open `http://<host>:8080` and log in as `admin`. Without `ROOKPARCEL_WEBUI_PASS`, `docker logs rookparcel` shows a temporary password. Stop it with `docker stop -t 60 rookparcel`, so it has time to save its torrents.

## Known limitations

- **What was tried.** Unit and swarm tests on Windows, Linux, macOS and FreeBSD, fuzzing, and a window test of the Windows program; the Linux and Mac fixes were tried on an Xubuntu and an Intel macOS VM. The storage hold was tested with folders removed and put back, not yet with a real USB disk, a `subst` drive or a network share. The release files were not started on a desktop before publishing.
- **An unreachable network share** is held only when Windows reports its files as not found; another error stops the torrent with that error, and it is not started again by itself.
- **On Linux, a mount unmounted while a torrent downloads** can still get files written into the empty mount point, since the folder itself is there.
- Everything in [1.2.67's limitations](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.76/docs/releases/1.2.67.md#known-limitations) still applies.
- **Do not use it on private trackers yet.** The client ID `RP` is not whitelisted anywhere.
