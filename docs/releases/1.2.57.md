**Rookparcel 1.2.57** looks after your settings across updates. If a new version reads your proxy or your network binding differently from the version that saved them, Rookparcel stops all transfers and asks you to check, instead of quietly connecting without them. It covers the development versions 1.2.55 and 1.2.56.

Rookparcel is a lean BitTorrent client in the spirit of µTorrent 2.2.1: small single-file binaries, a native look, low RAM and CPU use, and an interface that stays responsive with tens of thousands of torrents. The engine is our own Rust port of libtorrent-rasterbar 2.0.11; nothing is linked.

## New since 1.2.54

- **Settings checked after every update.** Each time Rookparcel saves its settings, it notes its version and how it read the settings that decide where your traffic goes: the proxy, Use only this network, the listen interfaces, encryption and the IP filter. The next version compares that note with its own reading of the file.
  - **A copy first.** After a version change, the settings file is copied beside it as `rookparcel.ini.<old version>.bak` (`webui.json.<old version>.bak` for `rookparcel-nox`). The last three are kept.
  - **Differences in the Logger.** Each setting that reads differently is listed, for example `proxy: socks5 10.8.0.1:1080 peers trackers names → none`.
  - **Nothing connects without your proxy.** If the proxy, the network rule or the listen interfaces would be lost, the transfers are held: nothing listens and no torrent connects, and the status bar says **Transfers held: confirm the settings**. Check Options > Preferences > Connection and press OK, and the transfers start. In the Web UI, save its Preferences page; the qBittorrent-compatible Web API, which automation calls, does not count as a confirmation. To go back instead, exit Rookparcel and copy the `.bak` file over the settings file.
  - **Nothing else goes out either.** RSS feeds, `.torrent` links, the tracker list and the update check wait as well, so a private tracker's feed address is not fetched without the proxy.
  - The wiki's [Updating Rookparcel](https://github.com/Balls0fSteel/Rookparcel/wiki/Updating-Rookparcel#when-a-version-reads-your-settings-differently) page explains it.
- **A proxy type this version cannot read no longer means "no proxy".** Before, a value written by a newer version read as a direct connection and was erased at the next save. Now the transfers are held, and the line stays in the file for the version that wrote it.
- **A settings file that cannot be read is never overwritten.** Before, Rookparcel took it for a first start: the Setup Guide opened and the next save replaced every setting. Now the transfers are held, nothing is saved over the file, and the Logger says why.
  - A settings file that is missing or empty while there are saved torrents is no first start either: the settings were lost, so the transfers are held and the Setup Guide does not open.
  - The settings are written to the disk before they replace the old file, so a crash or a power cut no longer leaves an empty file behind.
  - A file that is not valid text (saved by an editor in another encoding) is read as well as it can be, and the original is kept as `rookparcel.ini.damaged-<number>`.
  - A file saved by Notepad as "Unicode" (UTF-16) is read as it is.
- **`rookparcel-nox`: a damaged `webui.json` stops the start.** It names the file, so you can fix it or move it away. Before, nox replaced it with defaults and saved over it, losing the proxy, the labels and the login, also when started with `--webui-pass` (Docker).
- **`rookparcel-nox`: a network rule set with `--network` is read back at the next start.** It was stored under a key nox did not read. Rules stored by older versions are carried over, and the old key is still written beside the new one, so going back to 1.2.54 keeps the rule.
- **`rookparcel-nox`: the `* proxy:` line at start shows the proxy in force**, also one stored in the Web UI's preferences, and says when `--proxy` is not used.
- On Windows, Linux, macOS and in `rookparcel-nox`.

## Updating

- **Windows installer.** Rookparcel 1.2.5 and later offer the update themselves: Help > Check for Updates, then "Download and install". Settings and torrents are kept.
- **macOS.** Quit Rookparcel first, then drag the new `Rookparcel.app` to Applications over the old one.
- **Everything else.** Replace the program, the AppImage or the bundle as before. Settings and torrents are kept.
- **The settings check starts with this version.** 1.2.57 writes the first note at its first save. The update from 1.2.54 has nothing to compare yet, so it holds the transfers only if the file cannot be read or holds a proxy type it cannot read.
- **Remote control.** The remote protocol is now 19: a window and the `rookparcel-nox` it drives must both be 1.2.55 or later. 1.2.44 to 1.2.54 speak 18 and do not connect to 1.2.57.
- **Going back to an older version.** 1.2.54 and older keep the note's `check.` lines but do not update them. If you change the proxy or the network rule there and then update again, the new version lists the change in the Logger and holds the transfers until you confirm. 1.2.46 and older also ignore the lock PIN.
- **From before 1.2.45.** The seeding goal changed in 1.2.45: see [its notes](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.57/docs/releases/1.2.45.md#updating).
- **From PaTorrent.** PaTorrent does not offer this update. Install Rookparcel by hand, as in [1.2.5's notes](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.57/docs/releases/1.2.5.md#coming-from-patorrent).

## First run

The website's [install guide](https://balls0fsteel.github.io/Rookparcel/install.html) shows these steps one at a time.

- **Windows installer.** Run the setup. It is not code-signed, so SmartScreen shows "Windows protected your PC": click More info > Run anyway. "Install for anyone using this computer" asks for administrator rights and shows "Unknown publisher". Settings and torrents are in `%APPDATA%\Rookparcel`.
- **Windows zip.** Unzip anywhere and start `rookparcel.exe`; SmartScreen warns as above. An empty `rookparcel.ini` next to the exe keeps settings and torrents beside it (portable mode).
- **macOS.**
  1. Open the disk image and drag `Rookparcel.app` to Applications.
  2. The app is ad-hoc signed and not notarised, so Gatekeeper refuses it the first time. The disk image's `How to open Rookparcel.html` has these steps too.
     - macOS 15 Sequoia and newer: double-click the app and click Done in the warning. Open System Settings > Privacy & Security, scroll to Security and click Open Anyway (offered for about an hour), then confirm with your password or Touch ID.
     - macOS 11 to 14: Control-click (or right-click) the app, choose Open, then click Open.
     - Or, also when macOS says the app "is damaged", run `xattr -dr com.apple.quarantine /Applications/Rookparcel.app` in Terminal.
  3. macOS may ask whether Rookparcel may find devices on local networks. Allow it for peers and a Rookparcel daemon on your own network; downloads from the internet work either way.

  Settings and torrents are in `~/Library/Application Support/Rookparcel/mac`.
- **Linux AppImage.** Run `chmod +x Rookparcel-1.2.57-x86_64.AppImage`, then start it. Without FUSE 2 on the system, start it with `--appimage-extract-and-run`. Settings are in `~/.config/rookparcel/gtk`, torrents in `~/.local/share/rookparcel/gtk`.
- **Linux Flatpak.** The bundle holds the application; the runtime comes from Flathub:

  ```bash
  flatpak remote-add --if-not-exists --user flathub https://dl.flathub.org/repo/flathub.flatpakrepo
  flatpak install --user Rookparcel-1.2.57-x86_64.flatpak
  flatpak run io.github.balls0fsteel.Rookparcel
  ```

- **Headless.** `rookparcel-nox run --webui 8080 --webui-pass PASS` starts the daemon with its Web UI and a qBittorrent-compatible Web API on port 8080. [DAEMON.md](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.57/docs/DAEMON.md) describes services: systemd, FreeBSD rc.d, `--daemon` and Windows, one per profile if you like. Your own Web UI themes go in `webui/themes` under its settings folder (`/config` in Docker).
- **Docker.**

  ```bash
  docker run -d --name rookparcel -p 8080:8080 -p 6881:6881 -p 6881:6881/udp -e ROOKPARCEL_WEBUI_PASS=choose-one -v rookparcel-config:/config -v /srv/media:/downloads ghcr.io/balls0fsteel/rookparcel-nox:1.2.57
  ```

  Then open `http://<host>:8080` and log in as `admin`. Without `ROOKPARCEL_WEBUI_PASS`, `docker logs rookparcel` shows a temporary password. Stop it with `docker stop -t 60 rookparcel`, so it has time to save its torrents.

## Known limitations

- **What was tried.** Unit tests on Windows, Linux, macOS and FreeBSD. `rookparcel-nox` in scratch folders: with a proxy type it cannot read, and with a note made to look written by an older version that read a SOCKS5 proxy which now reads as none. Both times it started held, with nothing listening; the qBittorrent API's `setPreferences` applied a new port and kept the hold, and only the Web UI's Preferences save let the transfers go. Not tried: the status bar's "Transfers held" text in the Windows, Linux and Mac windows on a desktop. The release files were not started on a desktop before publishing.
- **The new texts are machine translations** in every language but English.
- **A Web UI hosted by a Windows window** cannot confirm the settings: press OK in that window's Preferences.
- **Copies keep old secrets.** The `.bak` and `.damaged-` copies keep the proxy password and the Web UI's password hash as they were, with the same file permissions as the settings file. Delete them after changing a password.
- **The search helper** (Jackett or Prowlarr, started by Rookparcel) makes its own connections to the indexers; a search while the transfers are held fails, but a helper that is already running is not stopped.
- **Keep ping low** still sends its ping probes while the transfers are held. They are not torrent traffic, and Use only this network does not bind them either.
- Everything in [1.2.0's limitations](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.57/docs/releases/1.2.0.md#known-limitations), [1.2.5's](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.57/docs/releases/1.2.5.md#known-limitations), [1.2.19's](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.57/docs/releases/1.2.19.md#known-limitations), [1.2.21's](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.57/docs/releases/1.2.21.md#known-limitations), [1.2.30's](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.57/docs/releases/1.2.30.md#known-limitations), [1.2.44's](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.57/docs/releases/1.2.44.md#known-limitations), [1.2.45's](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.57/docs/releases/1.2.45.md#known-limitations), [1.2.46's](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.57/docs/releases/1.2.46.md#known-limitations), [1.2.54's](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.57/docs/releases/1.2.54.md#known-limitations) still applies.
- **Do not use it on private trackers yet.** The client ID `RP` is not whitelisted anywhere.

## Reporting problems

Open an [issue](https://github.com/Balls0fSteel/Rookparcel/issues) with your platform, the file you used and what happened. For a crash or a stuck torrent, include the Logger tab or `rookparcel-nox run --verbose` output. On a Mac, Console.app's crash report for Rookparcel helps too. For security problems, see [SECURITY.md](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.57/SECURITY.md).
