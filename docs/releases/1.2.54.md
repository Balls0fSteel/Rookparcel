**Rookparcel 1.2.54** can lock its windows with a PIN, so that someone else at your computer cannot see your torrent list. It also fixes web seeds for one kind of v2 torrent, and a Linux window that a second stop signal could kill while it was saving. It covers the development versions 1.2.47 to 1.2.53.

Rookparcel is a lean BitTorrent client in the spirit of µTorrent 2.2.1: small single-file binaries, a native look, low RAM and CPU use, and an interface that stays responsive with tens of thousands of torrents. The engine is our own Rust port of libtorrent-rasterbar 2.0.11; nothing is linked.

## New since 1.2.46

- **Lock Rookparcel.** Choose Options > Lock PIN > Set PIN... and type a PIN of 4 to 6 digits. File > Lock Rookparcel (<kbd>Ctrl</kbd>+<kbd>L</kbd>, <kbd>⌘</kbd>+<kbd>L</kbd> on a Mac) then hides every Rookparcel window in the tray or the menu bar. Torrents keep downloading and seeding. In the Windows, Linux and Mac windows.
  - **Opening it again.** Click the tray icon, choose Show Rookparcel or start Rookparcel again: the "Rookparcel is locked" window asks for the PIN, and the windows that were open come back as they were. From the fifth wrong PIN in a row, each wrong PIN makes it wait 30 seconds.
  - **It stays locked.** Rookparcel exits locked and starts locked: it asks for the PIN at once, without showing its main window. Started at login with "Start minimized", it waits in the tray without asking.
  - **While it is locked**, the tray menu offers only Show Rookparcel and Exit; Exit works without the PIN. The "Download Complete" notification does not appear, since it names the torrent. Error messages, update offers and a magnet link's Add New Torrent window wait for the PIN. A `.torrent` file or magnet link opened while locked asks for the PIN first, and is not added on Cancel. The Auto Shutdown countdown still shows, so you can stop it.
  - **A forgotten PIN** is removed at start: hold <kbd>Ctrl</kbd> (Windows) or <kbd>⌥</kbd> Option (Mac) while you start Rookparcel, or start it with `--reset-lock` (Linux, and the others too). It asks "Remove the lock PIN?" first; torrents and other settings stay. If Rookparcel already runs, the running copy asks.
  - **It is a privacy screen, not security.** Nothing is encrypted; anyone who can edit `rookparcel.ini` or open the download folder can get past it. The PIN is kept as a salted hash. The Web UI is not locked: it has its own password. Each profile, and each window connected to a remote Rookparcel, has its own PIN or none.
  - The wiki's [Locking Rookparcel](https://github.com/Balls0fSteel/Rookparcel/wiki/Locking-Rookparcel) page has the steps for every system.
- **Fix: web seeds of a v2-only torrent with one file.** When the file's size was not a multiple of the piece size, Rookparcel asked the web seed for `<address>/<name>` instead of the address itself, got "404 Not Found" and never downloaded from it. libtorrent 2.0.11 does the same. v1 torrents were not affected.
- **Linux: a second stop signal no longer kills Rookparcel while it saves.** After a close begun by `SIGTERM` or <kbd>Ctrl</kbd>+<kbd>C</kbd> in its terminal, the GTK window waits for moving files and saves its torrents, showing "Rookparcel is closing". A second identical signal used to end it at once, mid-copy and without saving; now the close goes on. To stop it at once, use Quit Now in that window, or `kill -KILL`.
- **Linux: Minimize to tray** also works for a window first shown after the tray started: a profile's first window on GNOME, which waits a few seconds for its icon, and a locked start.
- **Local Peer Discovery at an interval of 0.** Preferences > Advanced accepts 0 for `local_service_announce_interval`, which made Local Peer Discovery send multicast packets every millisecond. An interval under 1 second now counts as 1 second, as in libtorrent 2.0.11.
- **Stricter JSON.** The Web UI and the search helper refuse a `\u` escape that is not four hex digits, such as `\u+041`.
- On Windows, Linux, macOS and in `rookparcel-nox`; the lock is only in the windows.

## Updating

- **Windows installer.** Rookparcel 1.2.5 and later offer the update themselves: Help > Check for Updates, then "Download and install". Settings and torrents are kept.
- **macOS.** Quit Rookparcel first, then drag the new `Rookparcel.app` to Applications over the old one.
- **Everything else.** Replace the program, the AppImage or the bundle as before. Settings and torrents are kept.
- **Going back to an older version.** 1.2.46 and older do not know the lock: they show their windows without asking for the PIN.
- **From before 1.2.45.** The seeding goal changed in 1.2.45: see [its notes](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.54/docs/releases/1.2.45.md#updating).
- **Remote control.** 1.2.44 to 1.2.54 speak the same remote protocol (18). Versions before 1.2.44 do not connect to them.
- **From PaTorrent.** PaTorrent does not offer this update. Install Rookparcel by hand, as in [1.2.5's notes](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.54/docs/releases/1.2.5.md#coming-from-patorrent).

## First run

The website's [install guide](https://balls0fsteel.github.io/Rookparcel/install.html) shows these steps one at a time.

- **Windows installer.** Run the setup. It is not code-signed, so SmartScreen shows "Windows protected your PC": click More info > Run anyway. "Install for anyone using this computer" asks for administrator rights and shows "Unknown publisher". Settings and torrents are in `%APPDATA%\Rookparcel`.
- **Windows zip.** Unzip anywhere and start `rookparcel.exe`; SmartScreen warns as above. An empty `rookparcel.ini` next to the exe keeps settings and torrents beside it (portable mode).
- **macOS.**
  1. Open the disk image and drag `Rookparcel.app` to Applications.
  2. The app is ad-hoc signed and not notarised, so Gatekeeper refuses it the first time. The disk image's `How to open Rookparcel.html` has these steps too.
     - macOS 15 Sequoia and newer: double-click the app and click Done in the warning. Open System Settings > Privacy & Security, scroll to Security and click Open Anyway (offered for about an hour), then confirm with your password or Touch ID.
     - macOS 11 to 14: Control-click (or right-click) the app, choose Open, then click Open.
     - Or, also when macOS says the app "is damaged", run `xattr -dr com.apple.quarantine /Applications/Rookparcel.app` in Terminal.
  3. macOS may ask whether Rookparcel may find devices on local networks. Allow it for peers and a Rookparcel daemon on your own network; downloads from the internet work either way.

  Settings and torrents are in `~/Library/Application Support/Rookparcel/mac`.
- **Linux AppImage.** Run `chmod +x Rookparcel-1.2.54-x86_64.AppImage`, then start it. Without FUSE 2 on the system, start it with `--appimage-extract-and-run`. Settings are in `~/.config/rookparcel/gtk`, torrents in `~/.local/share/rookparcel/gtk`.
- **Linux Flatpak.** The bundle holds the application; the runtime comes from Flathub:

  ```bash
  flatpak remote-add --if-not-exists --user flathub https://dl.flathub.org/repo/flathub.flatpakrepo
  flatpak install --user Rookparcel-1.2.54-x86_64.flatpak
  flatpak run io.github.balls0fsteel.Rookparcel
  ```

- **Headless.** `rookparcel-nox run --webui 8080 --webui-pass PASS` starts the daemon with its Web UI and a qBittorrent-compatible Web API on port 8080. [DAEMON.md](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.54/docs/DAEMON.md) describes services: systemd, FreeBSD rc.d, `--daemon` and Windows, one per profile if you like. Your own Web UI themes go in `webui/themes` under its settings folder (`/config` in Docker).
- **Docker.**

  ```bash
  docker run -d --name rookparcel -p 8080:8080 -p 6881:6881 -p 6881:6881/udp -e ROOKPARCEL_WEBUI_PASS=choose-one -v rookparcel-config:/config -v /srv/media:/downloads ghcr.io/balls0fsteel/rookparcel-nox:1.2.54
  ```

  Then open `http://<host>:8080` and log in as `admin`. Without `ROOKPARCEL_WEBUI_PASS`, `docker logs rookparcel` shows a temporary password. Stop it with `docker stop -t 60 rookparcel`, so it has time to save its torrents.

## Known limitations

- **What was tried.** The lock was run on Windows on a hidden desktop, in the Linux window under Xvfb with and without a tray, and in the Mac app on an Intel macOS VM. Not tried: holding <kbd>Ctrl</kbd> at start on a real Windows desktop (only a unit test covers it), <kbd>⌥</kbd> at launch on a real Mac, a real KDE or GNOME session, Apple silicon, and the dialogs at 125 % or 150 % scaling. The release files were not started on a desktop before publishing.
- **The lock's texts are machine translations** in every language but English, and the English wait message says "1 seconds" in its last second.
- **Exit while locked, with files still moving,** shows the "Rookparcel is closing" window, which names the folders the files are moving to.
- **Windows:** the "Remove the lock PIN?" question and "No lock PIN is set." get their own taskbar button. A locked start does not bring the main window back maximized, as with "Start minimized".
- **macOS:** with a second copy started from Terminal (as `--reset-lock` needs while Rookparcel runs) or with `open -n`, the running copy's question opens behind the window in front, without the keyboard: click it. Quit is greyed while the PIN window is open: click Cancel first. Opening the app again from Finder or the Dock works as expected.
- **Without a tray** (plain GNOME without the AppIndicator extension), there is nowhere to hide the windows: the "Rookparcel is locked" window takes their place, has no Cancel, and closing it quits Rookparcel.
- Everything in [1.2.0's limitations](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.54/docs/releases/1.2.0.md#known-limitations), [1.2.5's](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.54/docs/releases/1.2.5.md#known-limitations), [1.2.19's](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.54/docs/releases/1.2.19.md#known-limitations), [1.2.21's](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.54/docs/releases/1.2.21.md#known-limitations), [1.2.30's](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.54/docs/releases/1.2.30.md#known-limitations), [1.2.44's](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.54/docs/releases/1.2.44.md#known-limitations), [1.2.45's](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.54/docs/releases/1.2.45.md#known-limitations) and [1.2.46's](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.54/docs/releases/1.2.46.md#known-limitations) still applies.
- **Do not use it on private trackers yet.** The client ID `RP` is not whitelisted anywhere.

## Reporting problems

Open an [issue](https://github.com/Balls0fSteel/Rookparcel/issues) with your platform, the file you used and what happened. For a crash or a stuck torrent, include the Logger tab or `rookparcel-nox run --verbose` output. On a Mac, Console.app's crash report for Rookparcel helps too. For security problems, see [SECURITY.md](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.54/SECURITY.md).
