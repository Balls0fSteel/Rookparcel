**Rookparcel 1.2.69** makes the Trackers and Peers tabs sortable by their columns in the Windows, Linux and Mac programs, as the Files tab already was.

Rookparcel is a lean BitTorrent client in the spirit of µTorrent 2.2.1: small single-file binaries, a native look, low RAM and CPU use, and an interface that stays responsive with tens of thousands of torrents. The engine is our own Rust port of libtorrent-rasterbar 2.0.11; nothing is linked.

## New since 1.2.67

- **The Trackers and Peers tabs sort by their columns (all three programs).** Click a header to sort by it, click again to reverse, a third time to go back to the original order (the torrent's tiers for trackers, the order peers came in). Counts, %, speeds, requests and totals start with the most; names, addresses, clients, flags, status and Update In from the smallest.
  - Addresses sort by number. Peers that tie, on speed for example, stay in address order, so rows do not swap every second.
  - A tracker that has not reported a number stays at the bottom either way.
  - The list keeps its sort as peers come and go, and the selected peers or trackers stay selected. Each tab remembers its own sort.
- **This release also covers the development version 1.2.68** and fixes what its security review found: the sort now compares each row's text once per update, with long client names cut, and the Linux program keeps the selection of a sorted tab that is not shown. The engine, `rookparcel-nox` and the Web UI are as in 1.2.67.

## Updating

- **Windows installer.** Rookparcel 1.2.5 and later offer the update themselves: Help > Check for Updates, then "Download and install". Settings and torrents are kept.
- **macOS.** Quit Rookparcel first, then drag the new `Rookparcel.app` to Applications over the old one.
- **Everything else.** Replace the program, the AppImage or the bundle as before. Settings and torrents are kept.
- **The settings check of 1.2.57** finds nothing to hold for an update from 1.2.67. A tab's sort is stored only once you sort it.
- **Remote control.** The remote protocol is still 20: 1.2.69 and 1.2.63 to 1.2.67 drive each other.
- **Going back to 1.2.67** needs nothing: it ignores the Trackers and Peers sorts and shows those tabs in their original order.
- **From before 1.2.63.** Read [1.2.63's notes](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.69/docs/releases/1.2.63.md#updating) too: the remote protocol changed to 20, and going back below 1.2.63 with Append .!ut ticked needs it unticked first.
- **From before 1.2.45.** The seeding goal changed in 1.2.45: see [its notes](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.69/docs/releases/1.2.45.md#updating).
- **From PaTorrent.** PaTorrent does not offer this update. Install Rookparcel by hand, as in [1.2.5's notes](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.69/docs/releases/1.2.5.md#coming-from-patorrent).

## First run

The website's [install guide](https://balls0fsteel.github.io/Rookparcel/install.html) shows these steps one at a time.

- **Windows installer.** Run the setup. It is not code-signed, so SmartScreen shows "Windows protected your PC": click More info > Run anyway. "Install for anyone using this computer" asks for administrator rights and shows "Unknown publisher". Settings and torrents are in `%APPDATA%\Rookparcel`.
- **Windows zip.** Unzip anywhere and start `rookparcel.exe`; SmartScreen warns as above. An empty `rookparcel.ini` next to the exe keeps settings and torrents beside it (portable mode).
- **macOS.**
  1. Open the disk image and drag `Rookparcel.app` to Applications.
  2. The app is ad-hoc signed and not notarised, so Gatekeeper refuses it the first time. The disk image's `How to open Rookparcel.html` has these steps too.
     - macOS 15 Sequoia and newer: double-click the app and click Done in the warning. Open System Settings > Privacy & Security, scroll to Security and click Open Anyway (offered for about an hour), then confirm with your password or Touch ID.
     - macOS 11 to 14: Control-click (or right-click) the app, choose Open, then click Open.
     - Or, also when macOS says the app "is damaged", run `xattr -dr com.apple.quarantine /Applications/Rookparcel.app` in Terminal.
  3. macOS may ask whether Rookparcel may find devices on local networks. Allow it for peers and a Rookparcel daemon on your own network; downloads from the internet work either way.

  Settings and torrents are in `~/Library/Application Support/Rookparcel/mac`.
- **Linux AppImage.** Run `chmod +x Rookparcel-1.2.69-x86_64.AppImage`, then start it. Without FUSE 2 on the system, start it with `--appimage-extract-and-run`. Settings are in `~/.config/rookparcel/gtk`, torrents in `~/.local/share/rookparcel/gtk`.
- **Linux Flatpak.** The bundle holds the application; the runtime comes from Flathub:

  ```bash
  flatpak remote-add --if-not-exists --user flathub https://dl.flathub.org/repo/flathub.flatpakrepo
  flatpak install --user Rookparcel-1.2.69-x86_64.flatpak
  flatpak run io.github.balls0fsteel.Rookparcel
  ```

- **Headless.** `rookparcel-nox run --webui 8080 --webui-pass PASS` starts the daemon with its Web UI and a qBittorrent-compatible Web API on port 8080. [DAEMON.md](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.69/docs/DAEMON.md) describes services: systemd, FreeBSD rc.d, `--daemon` and Windows, one per profile if you like. Your own Web UI themes go in `webui/themes` under its settings folder (`/config` in Docker).
- **Docker.**

  ```bash
  docker run -d --name rookparcel -p 8080:8080 -p 6881:6881 -p 6881:6881/udp -e ROOKPARCEL_WEBUI_PASS=choose-one -v rookparcel-config:/config -v /srv/media:/downloads ghcr.io/balls0fsteel/rookparcel-nox:1.2.69
  ```

  Then open `http://<host>:8080` and log in as `admin`. Without `ROOKPARCEL_WEBUI_PASS`, `docker logs rookparcel` shows a temporary password. Stop it with `docker stop -t 60 rookparcel`, so it has time to save its torrents.

## Known limitations

- **What was tried.** Unit tests on Windows, Linux, macOS and FreeBSD, and a window test of the Windows program. The Windows program was pictured on a hidden desktop, the Linux program tried under a virtual X server on Xubuntu against a test daemon, and the Mac program on an Intel macOS VM: all three clicks, the sort kept across a restart, the selection following a peer through the updates. The test data gives every peer the same speeds and every tracker the same counts, so a sort by those columns was not seen changing the order live. The release files were not started on a desktop before publishing.
- **Windows and Linux** keep a selected peer or tracker by what it is only while the tab is sorted; unsorted, the selection stays on its row as before. The Mac follows the peer either way.
- Everything in [1.2.67's limitations](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.69/docs/releases/1.2.67.md#known-limitations) still applies.
- **Do not use it on private trackers yet.** The client ID `RP` is not whitelisted anywhere.

## Reporting problems

Open an [issue](https://github.com/Balls0fSteel/Rookparcel/issues) with your platform, the file you used and what happened. For a crash or a stuck torrent, include the Logger tab or `rookparcel-nox run --verbose` output. On a Mac, Console.app's crash report for Rookparcel helps too. For security problems, see [SECURITY.md](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.69/SECURITY.md).
