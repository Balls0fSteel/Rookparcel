**Rookparcel 1.2.46** no longer checks a whole torrent because one of its files is gone. When a virus scanner removed a single small file of a large torrent, every start read and hashed all of it again, and the torrents behind it on the same drive waited. Now only the missing file is downloaded again. The Logger also loses its most frequent line.

Rookparcel is a lean BitTorrent client in the spirit of µTorrent 2.2.1: small single-file binaries, a native look, low RAM and CPU use, and an interface that stays responsive with tens of thousands of torrents. The engine is our own Rust port of libtorrent-rasterbar 2.0.11; nothing is linked.

## New since 1.2.45

- **A missing file costs only its own pieces.** When Rookparcel starts a torrent, it compares what it saved with the files on disk. If a file was gone, it used to hash every file of the torrent. Now it keeps the pieces of the files that are there and downloads the missing file again. The Logger names it, for example "setup.exe is missing: 3 pieces to download again".
- **Where this shows.** Some virus scanners remove one file of a download, such as an installer, each time it is fetched. With a torrent of many gigabytes that meant a long check at every start, and "Checking 0.0 %" on every torrent that waited behind it on the same drive.
- **A file that is too short is still checked in full.** So is a torrent whose files cannot be read. Only a file that is plainly gone is handled the short way.
- **The Logger leaves out "received N peers".** The line came after every tracker answer, for every torrent and tracker, and pushed everything else out of view. The Trackers tab shows the same numbers. `rookparcel-nox run --verbose` still prints the lines.
- On Windows, Linux, macOS and in `rookparcel-nox`.

## Updating

- **Windows installer.** Rookparcel 1.2.5 and later offer the update themselves: Help > Check for Updates, then "Download and install". Settings and torrents are kept.
- **macOS.** Quit Rookparcel first, then drag the new `Rookparcel.app` to Applications over the old one.
- **Everything else.** Replace the program, the AppImage or the bundle as before. Settings and torrents are kept.
- **From before 1.2.45.** The seeding goal changed in 1.2.45: see [its notes](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.46/docs/releases/1.2.45.md#updating).
- **A file your virus scanner removes.** It is downloaded again at each start and removed again. To end that, exclude the download folder in the scanner, or set the file to Don't Download in the Files tab.
- **Remote control.** 1.2.44, 1.2.45 and 1.2.46 speak the same remote protocol (18). Versions before 1.2.44 do not connect to them.
- **From PaTorrent.** PaTorrent does not offer this update. Install Rookparcel by hand, as in [1.2.5's notes](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.46/docs/releases/1.2.5.md#coming-from-patorrent).

## First run

The website's [install guide](https://balls0fsteel.github.io/Rookparcel/install.html) shows these steps one at a time.

- **Windows installer.** Run the setup. It is not code-signed, so SmartScreen shows "Windows protected your PC": click More info > Run anyway. "Install for anyone using this computer" asks for administrator rights and shows "Unknown publisher". Settings and torrents are in `%APPDATA%\Rookparcel`.
- **Windows zip.** Unzip anywhere and start `rookparcel.exe`; SmartScreen warns as above. An empty `rookparcel.ini` next to the exe keeps settings and torrents beside it (portable mode).
- **macOS.**
  1. Open the disk image and drag `Rookparcel.app` to Applications.
  2. The app is ad-hoc signed and not notarised, so Gatekeeper refuses it the first time. The disk image's `How to open Rookparcel.html` has these steps too.
     - macOS 15 Sequoia and newer: double-click the app and click Done in the warning. Open System Settings > Privacy & Security, scroll to Security and click Open Anyway (offered for about an hour), then confirm with your password or Touch ID.
     - macOS 11 to 14: Control-click (or right-click) the app, choose Open, then click Open.
     - Or, also when macOS says the app "is damaged", run `xattr -dr com.apple.quarantine /Applications/Rookparcel.app` in Terminal.
  3. macOS may ask whether Rookparcel may find devices on local networks. Allow it for peers and a Rookparcel daemon on your own network; downloads from the internet work either way.

  Settings and torrents are in `~/Library/Application Support/Rookparcel/mac`.
- **Linux AppImage.** Run `chmod +x Rookparcel-1.2.46-x86_64.AppImage`, then start it. Without FUSE 2 on the system, start it with `--appimage-extract-and-run`. Settings are in `~/.config/rookparcel/gtk`, torrents in `~/.local/share/rookparcel/gtk`.
- **Linux Flatpak.** The bundle holds the application; the runtime comes from Flathub:

  ```bash
  flatpak remote-add --if-not-exists --user flathub https://dl.flathub.org/repo/flathub.flatpakrepo
  flatpak install --user Rookparcel-1.2.46-x86_64.flatpak
  flatpak run io.github.balls0fsteel.Rookparcel
  ```

- **Headless.** `rookparcel-nox run --webui 8080 --webui-pass PASS` starts the daemon with its Web UI and a qBittorrent-compatible Web API on port 8080. [DAEMON.md](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.46/docs/DAEMON.md) describes services: systemd, FreeBSD rc.d, `--daemon` and Windows, one per profile if you like. Your own Web UI themes go in `webui/themes` under its settings folder (`/config` in Docker).
- **Docker.**

  ```bash
  docker run -d --name rookparcel -p 8080:8080 -p 6881:6881 -p 6881:6881/udp -e ROOKPARCEL_WEBUI_PASS=choose-one -v rookparcel-config:/config -v /srv/media:/downloads ghcr.io/balls0fsteel/rookparcel-nox:1.2.46
  ```

  Then open `http://<host>:8080` and log in as `admin`. Without `ROOKPARCEL_WEBUI_PASS`, `docker logs rookparcel` shows a temporary password. Stop it with `docker stop -t 60 rookparcel`, so it has time to save its torrents.

## Known limitations

- **Not tried by hand.** The change ran in automated tests on Windows, one of them a restart after a file was deleted. The Linux and Mac programs were only compiled and checked for errors, and the release files were not started on a desktop before publishing.
- **A torrent that waits for its check says "Checking 0.0 %"**, like one that is being hashed. Checks run one at a time on each drive.
- **The line about a missing file is in English** in every language.
- Everything in [1.2.0's limitations](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.46/docs/releases/1.2.0.md#known-limitations), [1.2.5's](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.46/docs/releases/1.2.5.md#known-limitations), [1.2.19's](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.46/docs/releases/1.2.19.md#known-limitations), [1.2.21's](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.46/docs/releases/1.2.21.md#known-limitations), [1.2.30's](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.46/docs/releases/1.2.30.md#known-limitations), [1.2.44's](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.46/docs/releases/1.2.44.md#known-limitations) and [1.2.45's](https://github.com/Balls0fSteel/Rookparcel/blob/v1.2.46/docs/releases/1.2.45.md#known-limitations) still applies.
- **Do not use it on private trackers yet.** The client ID `RP` is not whitelisted anywhere.

## Reporting problems
